# HuddlersFire 의도 기준

사용자 기획 의도를 구현·검토의 기준으로 유지하는 문서다. AI의 선호나 측정 자료가 목적을 대신하지 않도록 **의도·사실·제안**을 분리한다. 2026-11-05 기획 의도를 보존한 필드 전면 재생성 승인(INT-18)까지 반영했다. 현재 구현은 [구조](architecture.md), 검토 이력은 [제품 검토](product-review.md), 실행 근거는 [검증](validation.md)에 둔다.

## 근거와 상태를 읽는 방법

- **확정**: 사용자가 직접 정했거나 구체적인 계획을 승인한 방향. 아래의 근거와 적용 범위까지 함께 읽는다.
- **관찰**: 코드·검사·실제 사용에서 확인한 사실. 구현돼 있다는 사실만으로 사용자 의도로 승격하지 않는다.
- **제안 / 미정**: AI의 해석·개선안 또는 아직 답하지 않은 선택. 실행 승인으로 취급하지 않는다.
- **보류**: 사용자가 이번 범위에서 미룬 사항. 새 요청이나 직접 관련된 결정 없이는 구현하거나 반복 제안하지 않는다.
- **대체됨**: 후속 결정으로 효력이 끝난 기준. 이력은 남기되 현재 규칙으로 적용하지 않는다.

## 현재 확정 의도

2026-11-06 INT-19 후속 사용자 **“배포 커밋 푸시해줘”** 요청으로 검증한 조명·그림자·재질 변경의 기존 사이트 배포와 원본 저장소 커밋·푸시를 승인했다. 앞선 로컬 전용 경계는 이번 검증본에 한해 대체한다. **공개 버전 31·규약 v19** 배포와 공개 파일/API 확인을 완료했고 기존 public 접근·DB·환경 리비전 1을 유지했다. 상세 결과는 [검증 기록](validation.md)에 남긴다.

2026-11-06 **INT-19 확정 — 접지·투영 그림자, 2D 조명과 노멀맵 구현**: 사용자가 웹 적용 사례·최적화를 검토한 뒤 전체 구현 계획을 요청하고 **“승인하고 구현”**을 선택했다. 구아슈 원화·세 맵·놀이·컬러/다크·원형 프로필과 전시 콘텐츠를 이어가며, 접촉/유한 높이 그림자·모닥불/랜턴 조명·형태 기반 노멀·WebGL/Canvas 호환 경로·제작/검증 하네스를 구현하고 로컬 검증한다. [조명 계약](lighting.md)을 따른다. 공유 물리·규약 v19·DB 스키마는 유지한다. 사진과 공식 전시 이미지의 원색·가독성을 보존한다. 이번 승인은 배포·커밋·푸시를 포함하지 않으며 공개 사이트는 버전 29다.

2026-11-06 INT-18 후속 사용자 **“배포 커밋 푸시 다 진행해줘”** 요청으로 검증한 새 필드의 기존 사이트 배포와 원본 저장소 커밋·푸시를 승인했다. 앞선 로컬 전용 경계는 이번 검증본에 한해 대체한다. **공개 버전 29·규약 v19** 배포와 공개 파일/API 확인을 완료했고 public 접근·DB·환경 리비전 1을 유지했다. 원본 main에는 연결된 UI/자산 전환과 새 필드·하네스·검증 기록을 함께 커밋한다.

2026-11-05 **INT-18 확정 — 게임 필드 기획 의도를 기준으로 배치·이미지 전면 재생성**: 사용자가 “게임 필드의 기획의도들만 남기고 내부 배치 및 이미지 전면 재생성”을 요청하고 해당 계획의 구현을 승인했다. 세 맵의 배치·캐릭터/동작·시설/지형/효과·카메라·필드 HUD를 새로 구성한다. 기존 그림·좌표·체형·프레임 수는 구현 이력으로 두며 새 기준 원화·전체 명세·대표 검토 후 전체 제작을 적용한다. 따뜻한 일러스트·컬러/다크·원형 프로필·공식 게임 콘텐츠·공유 기능과 놀이 규칙은 유지한다. 이전 하네스 작업의 전체 재생성 제외 경계와 필드의 기존 배치 고정은 이번 범위에서 대체한다. 구현·검증 승인으로 배포·커밋·푸시는 포함하지 않는다. 설계는 [필드 재구성](field-v2-design.md)을 따른다.

2026-11-05 INT-07 후속 계획 승인: 장면 명세·부분 제작·실제 합성 계약·실패 검사·소량 신규 자산 파일럿을 구현하고 검증한다. 기존 게임 물리·맵 크기·공유 기능과 공개 자산을 유지한다. 전체 자산 재생성·기존 화면 전면 수정·공개 배포는 이번 범위에 포함하지 않는다. 이 절차의 검토 통과는 사용자 실행/배포 권한을 대신하지 않는다.

위 후속 배포 승인에 따른 INT-17 결과: 기존 공개 사이트 **버전 28·규약 v18**에 반영했고 public 접근·DB·런타임 환경 리비전 1을 유지했다. 공개 파일 72개의 빌드 일치와 입장 API를 확인했다. 상세 근거는 [검증 기록](validation.md)의 INT-17 공개 배포 절을 따른다.

2026-11-05 INT-17 구현 이후 사용자가 **“배포해줘”**라고 요청해 검증된 일러스트 재구성본의 기존 공개 사이트 배포를 승인했다. 아래 최초 구현 승인의 배포 제외 경계는 이번 변경에 한해 대체한다. 기존 public 접근·DB·런타임 환경을 유지하며 게시 전용 소스 동기화는 배포 절차에 포함한다. 원본 GitHub 저장소의 커밋·푸시 요청은 아니다.

2026-11-05 **INT-17 확정 — sprite-gen 기반 일러스트 전면 재구성**: 사용자가 aldegad/sprite-gen 적용을 제안하고 “전면 교체 안으로 처음부터 다시 모두 재구성”하는 계획을 요청한 뒤 “계획대로 구현”을 승인했다. 캐릭터와 동작·세 맵의 지형/시설·불/장난감 효과·로비/게임 UI를 따뜻한 일러스트로 재구성한다. 생성 원본과 재현 가능한 로컬 제작 경로를 남기며 추출·아틀라스·게임 합성을 실제 연결한다. INT-15의 기하형 그림 기준은 대체하고 INT-16의 컬러/다크 개인 선택, Discord 사진·공식 게임 콘텐츠, 기존 게임/연결/음악/접근성 의미는 이어간다. 이번 승인은 구현·검증이며 **배포·커밋·푸시는 포함하지 않는다.** 아래 공개 버전 27·v17은 이전 배포 이력이며 현재 작업 소스는 v18이다.

2026-11-05 사용자 후속 **“배포해줘”** 요청으로 INT-16 컬러·다크 모드 변경의 기존 공개 사이트 배포를 승인했다. **공개 버전 27·규약 v17**로 배포 완료했으며 public 접근·DB·런타임 리비전 1을 유지했다. 아래 INT-16 초기 구현 승인의 배포 제외 경계는 이 후속 요청으로 이번 변경에 한해 대체한다.

2026-11-05 **INT-16 확정 — 컬러 모드·다크 모드 개인 설정**: 사용자 “컬러가 너무 칙칙해져서 컬러감 있는 모드랑 다크모드…설정에서” 요청과 계획 승인에 따라 설정에 두 모드를 제공한다. 컬러 모드를 기본값으로 하며 저장된 테마가 없는 기존 사용자도 컬러로 시작한다. 크림색 UI와 주황·초록·파랑 강조, 따뜻한 불빛·초록 지형·캐릭터 색을 적용하고 다크 모드는 기존 어두운 흑백 톤을 유지한다. 로비·UI·세 맵·필드/음악 PIP에 즉시 반영하고 개인 브라우저에 저장한다. 외부 콘텐츠 원색, 포탈 도형·선 패턴, 캐릭터 번호, 공유 상태·방 연결은 유지한다. **INT-14·15의 전체 흑백 고정을 두 모드 선택으로 대체**하며 SEED 재구축 구조는 유지한다. 승인 범위는 구현·검증이며 배포는 포함하지 않는다. 아래 버전 26 배포 기록은 이전 재구축에 대한 승인이다.

2026-11-05 INT-15 구현·검증 후 사용자 후속 **“배포해줘”** 요청으로 이번 재구축의 공개 배포를 승인했다. 기존 사이트에 **버전 26·규약 v17**로 배포 완료했고 public 접근·DB·런타임 리비전 1을 유지했다. 아래 초기 구현 승인에서의 배포 제외 경계는 이 후속 요청으로 이번 변경에 한해 대체한다.

2026-11-05 후속 **INT-15 확정 — 기존 시각 계층 철회와 SEED 기반 전면 재구축**: 사용자는 이전 결과가 제공한 GitHub 활용과 전체 재구성 의도에 미치지 못하고 단순 흑백 변경으로 보인다고 지적했다. 이어 “기존 시각적인 부분들을 전반적으로 철회 및 제거”, “github 링크를 활용하여 모두 새로 생성 및 변경”, “요소들도 잘 어우러지게 재구성”을 요청했고 **“계획대로 구현”**으로 승인했다. 공식 SEED 컴포넌트·스니펫을 실제 사용하고, 기존 스타일 덮어쓰기와 장면 그림을 제거하며 로비·입장·필드 중심 화면·패널·팝업과 직접 그리는 지형·오브젝트·캐릭터를 함께 재구성한다. INT-14의 UI/게임 필드 블랙앤화이트 범위와 외부 콘텐츠 원색 유지, 기존 커뮤니티·놀이·연결 기능은 이어간다. 이 승인은 구현·검증이며 이전 버전 25의 배포 승인을 새 변경에 확대하지 않는다.

아래 INT-14 도입·버전 25 배포는 **이전 부분 전환의 이력**이다. 전체 시각 재구축을 완료했다는 당시 해석은 INT-15로 정정한다.

2026-11-05 INT-14 구현·검증 이후 사용자 후속 **“배포해줘”** 요청으로 같은 변경의 기존 공개 사이트 배포를 승인했다. 공개 버전 **25**, 규약 **v16**, 기존 public 접근·DB·런타임 리비전 **1**을 유지해 배포 완료했다. 아래 초기 구현 승인에서의 배포 제외 경계는 이 후속 요청으로 이번 변경에 한해 대체된다. 상세 공개 결과는 [검증 기록](validation.md)을 따른다.

2026-11-05 후속 **INT-14 확정**: 사용자 “설치 및 구현 자체를 처음부터 다시…톤앤매너는 블랙앤화이트” 요청과 범위 답변 **“UI와 게임 필드에 적용”**, 계획 승인·구현 요청에 따라 SEED Design 기반으로 전체 앱 UI와 Canvas 필드를 흑백으로 재구성한다. 검정 배경·흰 주요 정보·회색 보조 정보를 사용하고, 포탈은 △ 놀이터·□ 전시장·○ 불멍과 선 패턴, 캐릭터는 여섯 명도와 Ⅰ~Ⅵ 표식, 모닥불 외형은 서로 다른 형태로 구분한다. 프로필 사진·게임 대표 이미지·트레일러 등 외부 콘텐츠는 원래 색을 유지한다. 이 결정은 기존 포탈 색·캐릭터 색·유색 모닥불 표현을 대체하며, 공간 구분·불 성장·개인 설정·P2P·방장 승계의 의미는 유지한다. 승인 범위는 구현·검증이며 공개 배포는 포함하지 않는다.

## 결정 변경과 충돌 처리

1. **현재 요청과 이미 받은 답부터 확인한다.** 상위 지침·권한 경계 안에서 최신의 명시적 사용자 결정을 해당 범위에 적용한다. 과거 문서·스킬·테스트가 이전 동작을 요구해도 이를 이유로 승인된 변경을 막지 않는다.
2. **사실과 목적을 분리한다.** 코드와 데이터는 현재 동작·제약·효과의 근거다. 불편이나 위험이 관측되면 구체적인 경험과 불확실성을 설명하되, “온기에는 보호가 필요하다” 같은 AI 해석을 확정 목적에 추가하지 않는다. 사용자가 원하는 동작과 구현 사실이 다르면 사실을 숨기지 않고 차이로 기록한다.
3. **분명한 변경은 실행한다.** 관련 의도 ID를 유지하면서 새 근거·범위·대체한 결정을 기록한다. 제품 안내·구현 계약·관련 검사·스킬 참조를 같은 작업에서 맞춘다. 합리적인 UI·코드 세부 선택마다 재승인을 받지 않는다.
4. **미해결 충돌만 좁혀 묻는다.** 같은 범위의 최신 요구끼리 양립할 수 없거나 사용자에게만 있는 결정이 필수일 때 영향과 선택 결과를 제시한다. 답이 필요한 부분만 보류하고 독립된 승인 작업은 계속한다. AgentHub의 질문 형식과 턴 종료 규칙을 따른다.
5. **기준을 고정하지 않는다.** 보류는 영구 금지가 아니고 확정 의도도 사용자가 바꿀 수 있다. 새로운 요청이 기존 기준을 대체하면 낡은 반대 규칙을 스킬에 남기지 않는다. 측정 결과만으로 의도를 자동 변경하거나 임의의 성능·편안함 임계값을 만들지 않는다.
6. **완료와 검증을 구분한다.** 승인→코드 반영→실행 검증→공개 배포는 서로 다른 상태다. 확인하지 않은 사실을 문서에 완료로 적지 않는다. 계획만 요청되면 조사와 대화 속 계획까지만 하고 이 문서도 수정하지 않는다.

## 하네스 구성

[AGENTS.md](../AGENTS.md)는 프로젝트 범위·의도 참조·스킬 선택의 진입점이다. 계획은 공통 `plan-interview`로 의도와 실행 범위를 정리하고, [제품 검토 스킬](../.agents/skills/camp-product-review/SKILL.md)은 실제 경험과 의도를 비교하며, [변경 검증 스킬](../.agents/skills/camp-change-validation/SKILL.md)은 승인한 동작을 검사한다. 2026-11-05 사용자가 `camp-plan-interview` 삭제와 공통 스킬 사용을 요청해 로컬 스킬과 기존 연결을 제거했다. 공통 스킬·전역 설정은 수정하지 않았다. 제품 의도를 각 스킬에 복제하지 않고 이 문서를 참조한다.

하네스 변경 때는 [사례](../.agents/skills/camp-product-review/references/intent-cases.md)로 적용·비적용·변경·충돌 경계를 검토한다. 이 규칙들은 프로젝트 안에서만 관리하며 전역 설정이나 사용자 공통 스킬을 고치지 않는다.
