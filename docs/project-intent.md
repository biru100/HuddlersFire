# HuddlersFire 의도 기준

사용자 기획 의도를 구현·검토의 기준으로 유지하는 문서다. AI의 선호나 측정 자료가 목적을 대신하지 않도록 **의도·사실·제안**을 분리한다. 2026-11-04 보호 제거 구현과 후속 배포 승인까지 반영했다. 현재 구현은 [구조](architecture.md), 검토 이력은 [제품 검토](product-review.md), 실행 근거는 [검증](validation.md)에 둔다.

## 근거와 상태를 읽는 방법

- **확정**: 사용자가 직접 정했거나 구체적인 계획을 승인한 방향. 아래의 근거와 적용 범위까지 함께 읽는다.
- **관찰**: 코드·검사·실제 사용에서 확인한 사실. 구현돼 있다는 사실만으로 사용자 의도로 승격하지 않는다.
- **제안 / 미정**: AI의 해석·개선안 또는 아직 답하지 않은 선택. 실행 승인으로 취급하지 않는다.
- **보류**: 사용자가 이번 범위에서 미룬 사항. 새 요청이나 직접 관련된 결정 없이는 구현하거나 반복 제안하지 않는다.
- **대체됨**: 후속 결정으로 효력이 끝난 기준. 이력은 남기되 현재 규칙으로 적용하지 않는다.

## 결정 변경과 충돌 처리

1. **현재 요청과 이미 받은 답부터 확인한다.** 상위 지침·권한 경계 안에서 최신의 명시적 사용자 결정을 해당 범위에 적용한다. 과거 문서·스킬·테스트가 이전 동작을 요구해도 이를 이유로 승인된 변경을 막지 않는다.
2. **사실과 목적을 분리한다.** 코드와 데이터는 현재 동작·제약·효과의 근거다. 불편이나 위험이 관측되면 구체적인 경험과 불확실성을 설명하되, “온기에는 보호가 필요하다” 같은 AI 해석을 확정 목적에 추가하지 않는다. 사용자가 원하는 동작과 구현 사실이 다르면 사실을 숨기지 않고 차이로 기록한다.
3. **분명한 변경은 실행한다.** 관련 의도 ID를 유지하면서 새 근거·범위·대체한 결정을 기록한다. 제품 안내·구현 계약·관련 검사·스킬 참조를 같은 작업에서 맞춘다. 합리적인 UI·코드 세부 선택마다 재승인을 받지 않는다.
4. **미해결 충돌만 좁혀 묻는다.** 같은 범위의 최신 요구끼리 양립할 수 없거나 사용자에게만 있는 결정이 필수일 때 영향과 선택 결과를 제시한다. 답이 필요한 부분만 보류하고 독립된 승인 작업은 계속한다. AgentHub의 질문 형식과 턴 종료 규칙을 따른다.
5. **기준을 고정하지 않는다.** 보류는 영구 금지가 아니고 확정 의도도 사용자가 바꿀 수 있다. 새로운 요청이 기존 기준을 대체하면 낡은 반대 규칙을 스킬에 남기지 않는다. 측정 결과만으로 의도를 자동 변경하거나 임의의 성능·편안함 임계값을 만들지 않는다.
6. **완료와 검증을 구분한다.** 승인→코드 반영→실행 검증→공개 배포는 서로 다른 상태다. 확인하지 않은 사실을 문서에 완료로 적지 않는다. 계획만 요청되면 조사와 대화 속 계획까지만 하고 이 문서도 수정하지 않는다.

## 하네스 구성

[AGENTS.md](../AGENTS.md)는 프로젝트 범위·의도 참조·스킬 선택의 진입점이다. [계획 스킬](../.agents/skills/camp-plan-interview/SKILL.md)은 의도와 실행 범위를 정리하고, [제품 검토 스킬](../.agents/skills/camp-product-review/SKILL.md)은 실제 경험과 의도를 비교하며, [변경 검증 스킬](../.agents/skills/camp-change-validation/SKILL.md)은 승인한 동작을 검사한다. 제품 의도를 각 스킬에 복제하지 않고 이 문서를 참조한다.

하네스 변경 때는 [사례](../.agents/skills/camp-product-review/references/intent-cases.md)로 적용·비적용·변경·충돌 경계를 검토한다. 이 규칙들은 프로젝트 안에서만 관리하며 전역 설정이나 사용자 공통 스킬을 고치지 않는다.
