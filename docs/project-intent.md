# HuddlersFire 의도 기준

사용자 기획 의도를 구현·검토의 기준으로 유지하는 문서다. AI의 선호나 측정 자료가 목적을 대신하지 않도록 **의도·사실·제안**을 분리한다. 2026-11-07 픽셀 쿼터뷰 제작 하네스 요청(INT-24)까지 반영했다. 현재 구현은 [구조](architecture.md), 검토 이력은 [제품 검토](product-review.md), 실행 근거는 [검증](validation.md)에 둔다.

## 근거와 상태를 읽는 방법

- **확정**: 사용자가 직접 정했거나 구체적인 계획을 승인한 방향. 아래의 근거와 적용 범위까지 함께 읽는다.
- **관찰**: 코드·검사·실제 사용에서 확인한 사실. 구현돼 있다는 사실만으로 사용자 의도로 승격하지 않는다.
- **제안 / 미정**: AI의 해석·개선안 또는 아직 답하지 않은 선택. 실행 승인으로 취급하지 않는다.
- **보류**: 사용자가 이번 범위에서 미룬 사항. 새 요청이나 직접 관련된 결정 없이는 구현하거나 반복 제안하지 않는다.
- **대체됨**: 후속 결정으로 효력이 끝난 기준. 이력은 남기되 현재 규칙으로 적용하지 않는다.

## 2026-11-07 원본 전달 정책 확정

사용자의 “아니 이거 zip자꾸 멈칫하는데 그냥 github업로드로 규칙화하자”와 “그래 가보자”에 따라 **GitHub를 새 미술 원본의 기본 저장소**로 사용한다. ZIP을 기본 전달 경로에서 빼고, 실제 PNG 바이너리·SHA256·출처·개별 승인 문서를 연결한다. ChatGPT가 직접 GitHub 바이너리 업로드를 수행할 수 있으면 검증까지 맡고 그렇지 않으면 Codex가 실제 받은 PNG를 손실 없이 업로드한다. 이미지가 업로드되지 않았으면 미완료로 남긴다. 원본 기록만으로 애니메이션/네이티브/게임 적용·배포가 승인되는 것은 아니다. [자산 레지스트리](../art/sprites/source-registry/README.md) 참조.

## 결정 변경과 충돌 처리

1. **현재 요청과 이미 받은 답부터 확인한다.** 상위 지침·권한 경계 안에서 최신의 명시적 사용자 결정을 해당 범위에 적용한다. 과거 문서·스킬·테스트가 이전 동작을 요구해도 이를 이유로 승인된 변경을 막지 않는다.
2. **사실과 목적을 분리한다.** 코드와 데이터는 현재 동작·제약·효과의 근거다. 불편이나 위험이 관측되면 구체적인 경험과 불확실성을 설명하되, “온기에는 보호가 필요하다” 같은 AI 해석을 확정 목적에 추가하지 않는다. 사용자가 원하는 동작과 구현 사실이 다르면 사실을 숨기지 않고 차이로 기록한다.
3. **분명한 변경은 실행한다.** 관련 의도 ID를 유지하면서 새 근거·범위·대체한 결정을 기록한다. 제품 안내·구현 계약·관련 검사·스킬 참조를 같은 작업에서 맞춘다. 합리적인 UI·코드 세부 선택마다 재승인을 받지 않는다.
4. **미해결 충돌만 좁혀 묻는다.** 같은 범위의 최신 요구끼리 양립할 수 없거나 사용자에게만 있는 결정이 필수일 때 영향과 선택 결과를 제시한다. 답이 필요한 부분만 보류하고 독립된 승인 작업은 계속한다. AgentHub의 질문 형식과 턴 종료 규칙을 따른다.
5. **기준을 고정하지 않는다.** 보류는 영구 금지가 아니고 확정 의도도 사용자가 바꿀 수 있다. 새로운 요청이 기존 기준을 대체하면 낡은 반대 규칙을 스킬에 남기지 않는다. 측정 결과만으로 의도를 자동 변경하거나 임의의 성능·편안함 임계값을 만들지 않는다.
6. **완료와 검증을 구분한다.** 승인→코드 반영→실행 검증→공개 배포는 서로 다른 상태다. 확인하지 않은 사실을 문서에 완료로 적지 않는다. 계획만 요청되면 조사와 대화 속 계획까지만 하고 이 문서도 수정하지 않는다.

## 하네스 구성

[AGENTS.md](../AGENTS.md)는 프로젝트 범위·의도 참조·스킬 선택의 진입점이다. 계획은 공통 `plan-interview`로 의도와 실행 범위를 정리하고, [제품 검토 스킬](../.agents/skills/camp-product-review/SKILL.md)은 실제 경험과 의도를 비교하며, [변경 검증 스킬](../.agents/skills/camp-change-validation/SKILL.md)은 승인한 동작을 검사한다. 2026-11-05 사용자가 `camp-plan-interview` 삭제와 공통 스킬 사용을 요청해 로컬 스킬과 기존 연결을 제거했다. 공통 스킬·전역 설정은 수정하지 않았다. 제품 의도를 각 스킬에 복제하지 않고 이 문서를 참조한다.

하네스 변경 때는 [사례](../.agents/skills/camp-product-review/references/intent-cases.md)로 적용·비적용·변경·충돌 경계를 검토한다. 이 규칙들은 프로젝트 안에서만 관리하며 전역 설정이나 사용자 공통 스킬을 고치지 않는다.

2026-11-05 후속 요청 “배포해주고 확인이 필요한건 질문해줘”로 INT-09·10 구현의 공개 배포를 승인했다. 기존 공개 사이트 버전 16·규약 v14로 배포했고 실제 Discord 동의·음향 청취 확인은 구현 및 배포 결과와 구분한다.

2026-11-05 공개 사용 피드백: 모닥불 음량 조절 문제를 고치고 “모닥불 음량” 표기를 “효과음 음량”으로 바꾸도록 요청했다. 개인 소리 설정은 모닥불·장작 등 현재 효과음 전체를 관리하며 음악과 독립으로 유지한다. 새 효과음 종류의 추가 요청은 아니다.

2026-11-05 장작 성장 후속 승인: INT-09의 통나무 근접 E 개선, 개인 장작 간격 10분, 방 단위 공동 경험치·레벨 및 외형 공유를 구현·검증한다. 개인 계정의 영구 성장이나 DB 영구 월드는 선택하지 않았다. 구체적인 XP 수치·레벨 상한·외형 구성은 변경 가능한 구현 세부이며 사용자 목적 자체로 고정하지 않는다. 이번 승인은 공개 배포를 포함하지 않는다.

2026-11-05 장작 성장 후속 배포 요청: 사용자 “배포해줘”에 따라 위 INT-09 변경의 기존 공개 사이트 배포도 승인됐다. 버전 18·규약 v15로 배포하고 공개 응답·빌드 파일 일치를 확인했다. 공개 접근·DB·서버 환경 리비전 1은 유지했다.

2026-11-05 신청곡·이름표·휠 후속 승인: INT-06의 첫 신청/대기열 소진 후 신청 자동 시작, INT-04의 지형에 가려지지 않는 이름표, INT-03의 필드 마우스 휠 확대·축소 계획을 구현·검증한다. 수동 일시정지·개인 음소거·맵 분리·PIP 연결은 유지하며 왼쪽 상단 확대/축소/배율 표시를 제거한다. 이번 승인은 구현·검증에 한정하고 공개 배포는 포함하지 않는다.

2026-11-05 모바일 라디오 후속 요청: 영상 없는 라디오 검토 후 사용자가 “youtube는 그럼 그냥 유지”를 선택했고 이어 “모바일에서만 좀 축소”를 요청했다. INT-06의 YouTube 영상과 공동 재생을 유지하면서 모바일 창의 여백·안내·미지원 기능을 줄인다. 영상을 숨기거나 오디오 전용 소스로 바꾸지 않으며 데스크톱 기본 배치는 유지한다. 이번 변경은 로컬 구현·검증이며 공개 배포 요청은 아니다.

2026-11-05 후속 “배포하고 커밋 푸시도 해줘”: INT-03·04·06의 신청곡 자동 시작·지형 위 이름표·휠·모바일 라디오 축소 변경의 공개 배포와 프로젝트 원본 저장소 커밋·푸시를 승인했다. 앞선 해당 변경의 미배포 경계를 대체한다. 공개 버전 19·규약 v15로 배포하고 기존 public 접근·DB·환경 리비전 1을 유지했다. 원본 main에는 아직 미커밋이던 앞선 승인된 맵·통나무·공동 성장 등 연결된 변경과 이번 검증/배포 문서를 함께 기록하는 범위를 포함한다.
