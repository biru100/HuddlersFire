## INT-22 참가자 피드백 · 로컬 소스

사용자 후속 배포 요청으로 **공개 버전 38·규약 v20**에 반영했다. 전송 필드·DB·규약은 바꾸지 않았다. 상태 선택은 `PresenceEditor`의 세 버튼 한 곳에서 즉시 저장한다. 메모 초안은 상태 값을 복제하지 않으며 저장 시 최신 상태와 합친다. 저장 성공 후 서버의 500ms 갱신 간격까지 중복 제출을 막는다. `presenceSummary`로 기본 상태와 한마디를 머리 위/사람 목록에 표시하며 작업 내용도 사람 목록에 보인다. 긴 한마디의 전체 내용은 플레이어 정보에서 확인한다.

카메라는 따라가기·자유 시점·전체 보기를 구분한다. `camp-input.mjs`는 마우스 8px 초과 드래그부터 선택을 취소하고 캡처된 포인터 이동을 전달한다. `camp-camera.mjs`의 자유 시점은 기존 투영 중심과 배율을 보존하고 휠 위치를 기준으로 확대한다. 착석은 카메라를 바꾸지 않으며 높은 연쇄 자동 맞춤은 전체 보기에서만 적용한다. 따라가기 복귀도 선택한 줌을 유지한다. 공유 좌표와 물리는 변경하지 않는다.

앱은 렌더러에 `theme:'color'`와 개인 `uiTheme`를 따로 전달한다. 필드·캐릭터·불은 컬러를 유지하고 이름표·패널·조작 UI는 개인 테마를 사용한다. 렌더러의 직접 다크 자산 경로는 과거 자산 재현/제작 검사용이다. 라디오는 화면 안에 있을 때만 연결선 없는 말풍선을 배치하고 일반 채팅 연결선은 유지한다.

신규/설정 없는 사용자의 효과음은 25%이며 저장한 0과 이전 `forestVolume:0`은 보존한다. `CampAudio`가 muted/blocked/loading/failed/outside/playing 상태를 구독자에게 알리고 `EffectsStatus`가 설정·라디오·필드 안내에서 같은 상태와 켜기/재시도를 제공한다. 오디오 파일 실패를 조용히 삼키지 않으며 음량과 라디오의 개인 듣기는 독립적이다.

## INT-21 배포 식별과 자동 업데이트

이 기능은 **버전 37·규약 v20**에 처음 공개했고 현재 INT-22의 버전 38에도 유지한다. 아래 INT-20 버전 36은 기존 시각 개선본의 공개 이력이다. 구 소스로 되돌릴 때도 새 빌드를 만들어 더 최신 revision으로 게시한다. 과거 바이너리를 그대로 다시 활성화해 배포 fence를 되돌리지 않는다.

`run-framework.mjs build`가 빌드마다 UUID와 시간 순서 revision을 한 번 만들고 Vite define으로 브라우저·Worker에 동일하게 넣는다. 직접 `vite build` 대신 기존 `npm run build` 경로를 사용한다. `camp-release.mjs`는 새 `camp_runtime` 단일 행과 D1 트랜잭션으로 더 최신 빌드의 최초 활성화에서만 방을 삭제한다. FK cascade로 참가자·시그널을 함께 정리하고 로그인·프로필·OAuth·개인 설정은 보존한다. 구 Worker는 최신 revision을 되돌리거나 새 방을 삭제할 수 없다. 생성/참가 SQL도 같은 release fence를 검사한다.

`/api/camp/version`과 API 응답의 `X-Camp-Release`/`X-Camp-Revision`은 캐시하지 않는다. 방의 일반 HTTP 응답에서 업데이트를 즉시 감지하며 로비·솔로도 15초마다, 창 활성화/복귀 시 확인한다. 이전 revision의 늦은 응답은 재시도하며 뒤로 업데이트하지 않는다. `useCampSession`은 업데이트를 한 번만 받아 연결을 종료하고 Camp가 입력·PIP·솔로·음악 표시를 정리한다. 초대 room 파라미터는 제거하고 캐시 우회 URL로 새 로비를 로드한다. 같은 목표 버전에 60초 안에 반복 실패하면 재탐색을 멈춰 무한 새로고침을 방지한다. 일반 네트워크 장애는 초기화/새로고침의 근거가 아니다.

마이그레이션 `0004_release_reset`은 새 runtime 테이블만 만든다. 배포 시 SQL을 포함하며 이전 migration을 수동 재적용하지 않는다. 이 기능 이전의 v36 방은 기존 HTTP 410 종료 경로로 새로고침된다. 감시 코드가 없는 이전 로비/솔로 페이지는 한 번 새로고침해야 하며 이후 배포부터 자동 감지가 적용된다. 브라우저가 완전히 중지된 동안 실행을 강제할 수 없으므로 해당 탭은 복귀 시 확인한다.

## INT-20 현재 공개본 · field-polish-v1 / 버전 36·규약 v20

2026-11-06 사용자 후속 **“배포해줘”** 요청으로 아래 검증본을 기존 사이트 **버전 36·규약 v20**에 배포했다. 공개 파일 102개와 API를 확인했으며 public 접근·DB·환경 리비전 1은 유지했다. 아래 버전 35는 이전 공개 이력이다.

현재 로컬 소스는 장면 구성 개선본이다. `camp-camera.mjs`가 HUD/영상 점유 공간, 기본 따라가기·전체 보기·높은 업기 예외를 계산한다. `camp-renderer.mjs`는 화면 픽셀 이름표와 선택 영역을 함께 배치하고 표시용 마지막 이동 방향을 캐시하며 공유 플레이어 상태는 변경하지 않는다. `camp-character.mjs`와 애니메이션 모듈이 앞/뒤 기본 얼굴·몸을 연결하고 사진은 반전 없이 보존한다.

`camp-maps.mjs`의 비대칭 좌석군은 기존 seat ID·16석·네 방향을 유지한다. 새 벤치의 접촉 보정·시설 크기·가림·그림자 마스크는 `camp-scene-contract.mjs`를 공유한다. 공터/길의 비정형 가장자리는 표시 전용이며 이동 경계는 기존 논리 경계를 사용한다. 배치 혼용을 방지하도록 로컬 규약을 v20으로 올렸고 DB와 전송 필드 구조는 유지한다.

`field-polish-v1/artwork`에는 명시한 기존 원본 47개와 새 원본 12개·생성 지시·영수증·동결 앵커를 보존한다. `release`에는 27개 런타임 PNG, 재질 명세와 43개 실제 검토 화면을 보존한다. 기본 자산 재현은 `material-release.json`의 이 묶음을 사용한다. 공개본과 로컬 소스를 구분하며 아래 버전 35는 공개 이력이다.

이전 공개본은 **버전 35·규약 v19**, **`field-night-v1` 불멍 야간 조명과 Discord 프로필 사진 복구**다. `sceneLighting`의 맵별 주변광/직접광을 WebGL과 Canvas가 공유하고, 세계 거리·높이로 감쇠를 계산한다. 노멀 강도와 기본 노출은 분리하며 기본 얼굴은 둥근 노멀 캐시, Canvas는 제한된 프레임 색 보정 캐시를 사용한다. `createDrawContext`가 두 경로의 사물·재질 구분을 보존한다. `data-camp-lighting`으로 밤 필드 위 상태 글자 대비를 조정하고, 놀이터·전시장의 기존 표현과 사진·미디어·이름표를 유지한다. [조명 계약](lighting.md)과 33개 검토를 따르며 공개 파일 84개/API를 확인했다. public 접근·DB·환경 리비전 1을 유지했다.

사진 중계는 Workers가 지원하는 `redirect: 'manual'`과 응답 상태 검사로 리다이렉트를 거절한다. 지원하지 않는 `error` 옵션 때문에 발생하던 502를 수정했다. 로비의 장면 상태와 입장 전 미리보기 캐릭터에도 `profile.avatar`를 전달하며, 작은 미리보기·큰 로비·실제 필드가 같은 사진을 사용한다. Worker 런타임 회귀와 모의 Discord 사진을 쓰는 격리 브라우저 검사 `browser.avatar.mjs`로 확인한다.

앞선 **버전 32·규약 v19**는 스프라이트 윤곽 그림자 수정본 `field-shadow-v4`의 배포 이력이다. 색/마스크는 `camp-scene-contract.mjs`의 같은 시설 크기·방향·착석 표시 보정을 사용한다. `GroundShadows.draw`가 사물 이전에 접촉과 alpha 윤곽 투영을 그리며, 지면 경계 clip과 공통 광원 선택은 WebGL/Canvas가 공유한다. v3에서 약했던 농도와 거리 감쇠를 보정했다. 사용자 후속 배포 요청으로 반영했고 공개 파일 84개와 API를 확인했다. public 접근·DB·환경 리비전 1은 유지했다. 아래 공개 버전 31은 최초 조명 배포 이력이다.

## INT-19 조명·재질 런타임 · 공개 버전 31 / 규약 v19

노멀 조명은 [조명 계약](lighting.md)을 따른다. 기존 `CampRenderer`가 입력·카메라·그리기 순서를 소유하고 공통 투영/정렬과 기록 어댑터를 통해 PixiJS WebGL2 필드로 전달한다. ## INT-18 필드 v2 · 공개 버전 29

최신 공개 규약은 v19다. 사용자 후속 요청으로 2026-11-06 공개 버전 29에 반영했고 public 접근·DB·환경 리비전 1을 유지했다. 배치·스폰·좌석·포털·전시대와 `routes/clearing`은 `camp-maps.mjs`가 소유하고, renderer/artwork가 같은 좌표를 투영한다. 네 면의 벤치군은 두 그림 축과 네 착석 몸 방향에 연결된다. 물리 좌석은 공유 상태로 유지하며 좌면/지면 메타데이터의 보정은 표시에서만 적용한다.

`camp-sprite-animation.mjs`는 방향별 sit과 프레임별 고정 원형 머리 앵커를 사용한다. 혼합 자세는 하체의 머리 높이에 상체를 맞추고, 좌석 감정은 불을 향한 재킷·골반을 유지하며 팔을 합성한다. 이름표는 머리·몸과의 겹침을 피하고 실제 선택 영역도 새 위치로 갱신한다. 높은 연쇄는 전체 높이를 적용한 뒤 카메라를 맞춘다.

`tools/lib/field-assets.mjs`는 이전 manifest를 가져오지 않는 v2 빌드/설치 소유자다. 전체 목록·고정 앵커·실제 Canvas/UI 검토가 없으면 설치하지 않는다. 이전 v1 재패킹은 이력 재현 경로로 남는다. 기본 `scene-spec.json`은 전체 v2이며 작은 v1 명세는 `art/sprites/examples/`에 있다. 새 원본과 생성 출처는 `art/sprites/field-v2/`에 보존한다. 필드 HUD는 `web/app/field-v2.css`, 비어 있는 라디오는 접힌 상태·재생 중 영상은 기존 최소 200×200 규칙을 사용한다.

2026-11-05 사용자 후속 배포 승인으로 아래 INT-17 구현을 **공개 버전 28·규약 v18**에 반영했다. public 접근·DB·환경 리비전 1을 유지했으며 공개 결과는 [검증 기록](validation.md)을 따른다. 아래 구현 당시의 미배포 표기는 이 후속 결과로 대체한다.

## sprite-gen 일러스트 런타임 (2026-11-05, INT-17·로컬 v18)

후속 authoring 구현은 [제작 경로](sprite-authoring.md)를 따른다. `createSpriteContext`는 manifest·이미지 로더·캐시를 인스턴스별로 소유하고 기본 export는 정식 자산의 호환 API다. `CampRenderer`의 선택적 assets 인자로 파일럿을 주입하며, character/animation/artwork도 같은 context를 사용한다. `camp-scene-contract.mjs`가 좌석 접선 방향과 그림 접촉점의 표시 보정을 계산하고 새 메타데이터의 background/foreground 깊이를 renderer가 사용한다. 사진 방향·공유 좌표·좌석/충돌/규약 v18은 변경하지 않는다. 새 동작 전체의 방향/색/다크 제작은 별도다.

`scene-spec.json`의 작업 스냅샷에서 프롬프트/요청과 preview manifest를 만든다. `--job`은 선택 입력만 공식 slice/tile 도구로 처리하고 `art/sprites/runs/` 안에 출력한다. `CAMP_PREVIEW_JOB`의 Vite 플러그인은 serve 때만 메모리의 manifest와 loopback 파일 응답을 제공하며 production build에는 활성화되지 않는다. 전체 신규 생성 준비에는 같은 명세의 시각 검토가 필요하다. 기술 정합성 검사는 미감 자동 판정과 구분한다.

이 절이 현재 소스 계약이다. 아래 공개 버전 27/26·v17의 그림과 팔레트 구현은 이전 이력이다. `camp-character.mjs`와 `camp-artwork.mjs`의 기하형 그리기를 sprite atlas 합성으로 교체했다. `camp-sprite-animation.mjs`가 16상태/63프레임의 선택·대표 자세·상하체 조합을 소유하고, `camp-sprite-assets.mjs`가 lazy load·실패 재시도·16개 decoded 캐시를 소유한다. `camp-sprite-manifest.mjs`는 빌드 산출물이다. 자세·앵커·출처·재생성은 [자산 계약](sprite-assets.md)에 기록한다.

`CampRenderer`는 카메라·선택·이름표·말풍선·깊이 정렬을 계속 소유한다. ground는 맵/테마별 offscreen surface로 캐시하고 화면 밖 장식은 그리지 않는다. 사진은 원형 머리에 중앙 crop하며 반전하지 않는다. 그림 손을 사진 위로 합성한다. 다크 atlas는 미리 생성하고 외부 사진/부스/영상은 원색으로 유지한다. 여섯 톤 이외의 이전 색 값도 그림에서는 기존 toneIndex 슬롯으로 표시하며 프로필 원본 데이터는 보존한다.

`camp-scene-layout.mjs`는 비충돌 장식, `camp-maps.mjs`는 실제 시설·충돌·상호작용 배치다. 주변 배치를 새로 구성하고 들기 간격을 `CARRY_GAP=1.65`로 조정해 16인 탑의 얼굴 선택 영역을 분리했다. 규약 v18로 다른 간격/충돌 배치를 시뮬레이션하는 v17 클라이언트를 거절한다. DB·wire 필드·포탈/좌석/부스 ID는 유지한다.

UI는 SEED 동작 컴포넌트를 유지하고 큰 그림 미리보기/입장 카드 로비, 둥근 필드와 별도 패널, 그림 브랜딩으로 재구성했다. `sprite-art.tsx`가 게임과 같은 sheet를 UI에서 재사용한다. 로딩 상태와 수동 재시도는 `Camp`가 renderer callback으로 표시한다. 테마 전환/패널 접기에서 Canvas·연결·초안을 재생성하지 않는다. 신규 제작 스킬은 프로젝트 로컬 `camp-sprite-assets`이며 생성 도구·원본은 런타임 번들에 포함하지 않는다. 공개 배포는 하지 않았다.

## 개인 화면 테마 (2026-11-05, INT-16·공개 버전 27·규약 v17 유지)

현재 화면은 컬러(기본)·다크 두 모드다. 아래 INT-15의 흑백 고정 설명은 이전 배포 이력이다. `camp-settings.mjs`의 `theme: color | dark`는 개인 localStorage에만 저장하며 누락·잘못된 값은 color로 정규화한다. 음량·음소거·들기 동의 마이그레이션은 보존한다. 저장소 사용이 불가능하면 세션 메모리에서 선택을 유지한다.

`camp-theme.mjs`의 자체 완결된 applyTheme를 layout의 첫 렌더 스크립트와 실행 중 화면에 함께 사용한다. getSettingsSnapshot으로 hydration 기본값이 저장된 다크 모드를 덮어쓰지 않게 한다. 문서 루트의 data-camp-theme와 SEED light-only/dark-only를 함께 바꾸고, useCampPip은 필드·음악 새 창과 이미 열린 창 모두 같은 선택을 따라간다. 로컬 저장소 이벤트는 같은 출처의 다른 탭에도 반영한다.

CampRenderer는 매 프레임 scene.theme를 읽어 이미 생성된 Canvas에 팔레트만 바꾼다. CampArtwork는 지형·시설·포탈·불의 색, characterColor는 기존 여섯 무채색 프로필 슬롯의 로컬 색 표시를 맡는다. 기존 유색 프로필은 컬러에서 원색, 다크에서 명도로 표시한다. 로비 선택 견본·캐릭터 미리보기·참가자 상세도 같은 변환을 사용한다. 외부 사진·부스 이미지에는 필터를 적용하지 않는다. 포탈 도형/패턴·캐릭터 번호·불의 다섯 형상과 물리·좌표·전송 필드·DB·v17 규약은 유지한다.


## SEED 기반 시각 계층 재구축 (2026-11-05, INT-15·공개 버전 26·규약 v17)

공개 버전 25·v16은 이전 흑백/일부 컴포넌트 전환본이다. 당시 소스는 사용자가 다시 승인한 전체 재구축이며 후속 배포 요청으로 **공개 버전 26·규약 v17**에 반영했다. 기존 public 접근·DB·환경 리비전 1을 유지했다.

공식 SEED CLI로 ActionButton, TextField, Tabs, Avatar, Badge, List, Select, SelectBox, Snackbar, Callout, ResultSection 등을 생성하고 실제 화면에 연결했다. 패키지는 React 3.1.1, CSS/Tailwind theme 3.1.0, Vite plugin 2.1.1이다. seed-design.json은 프로젝트 내부 RSC/TSX 경로와 telemetry:false를 선언한다. 스니펫의 출처 주석을 유지하며 빈 interface를 type alias로 바꾸고 displayName을 보완했다. ActionButton의 공통 기본값은 neutralWeak/medium이고 중요한 행동과 선택 상태는 각 호출부에서 명시한다. 기존 클래스명으로 variant를 추론하지 않는다.

기존 components/ui/ 61개, components.json, seed-design/ui/controls.tsx와 사용하지 않는 UI 패키지를 제거했다. form-controls.tsx는 SEED TextField/Slider/Switch의 앱 어댑터다. choice-field.tsx는 공식 Select 스니펫을 사용한다. dialog.tsx는 SEED Dialog/Portal과 PIP 대상 문서를 연결하고 FocusScope의 실제 unmount 이벤트에서 Canvas 포커스를 복구한다.

app/globals.css의 이전 시각 규칙은 제거했다. camp-theme.css는 무채색 토큰만, 새 camp-layout.css는 화면 배치·반응형·겹침 순서를 담당한다. 로비는 소개/미리보기와 프로필 준비/공개방 목록으로 나누고 생성·코드 입장은 별도 Dialog로 제공한다. 방 화면은 필드와 SEED Tabs 패널이다. 모바일/필드 모드는 SEED BottomSheet이며 닫을 때 positioner를 hidden 처리하고 내용은 유지해 초안·읽던 위치를 보존한다. 패널 크기 버튼을 제공하고 터치 환경의 키보드 보정은 SEED에 맡긴다. 데스크톱과 키보드 없는 미리보기에서는 입력 높이 고정을 해제해 크기 변경을 적용한다. Snackbar, Callout, ResultSection이 알림·오류·빈 상태를 제공한다.

camp-artwork.mjs가 새 무광 기하형 바닥·나무·텐트·좌석·라디오·포탈·부스·불·장난감 효과를 그린다. CampRenderer는 이를 상속하고 카메라·선택·말풍선·이름표 배치를 담당한다. camp-character.mjs는 둥근 사각 얼굴과 간결한 몸통으로 다시 그리되 기존 자세/동작 계산을 사용한다. 외부 프로필·게임 이미지는 원색을 유지한다. 여섯 명도/번호, 포탈 표식/선 패턴, 다섯 불의 서로 다른 형상은 reduced-motion에서도 구분된다. 모바일은 라디오가 차지하는 영역 위로 카메라 중심을 옮긴다.

맵 외곽으로 장식/충돌물을 재배치했으므로 구버전의 다른 충돌 배치와 함께 시뮬레이션하지 않도록 규약을 **v17**로 올렸다. wire 필드·DB 스키마·포탈/좌석/부스 상호작용 ID는 유지한다. 아래 v16 맵 도입 절의 범위와 이동 규칙은 유지하되 현재 배치와 버전은 이 절을 따른다.

검증은 단위/Canvas, 격리 headless Chromium의 입장·다섯 탭·포커스·패널 크기·PIP·모바일 겹침, 16인 루프백 RTC를 구분한다. 실행 결과와 실기기/외부 서비스 미검증 범위는 검증 기록을 따른다.

## 전시 부스 공통 템플릿 (2026-11-05, 규약 v16 유지·공개 버전 24)

INT-13에 따라 `camp-games.mjs`의 `createGameExhibit`를 공통 데이터 형식으로 사용한다. 로고·필드 대표 이미지·YouTube 트레일러·SNS·소개/관련 링크를 게임 ID로 조회하고, 필드와 팝업이 같은 항목을 참조한다. 추가 게임·배치 예제는 [부스 템플릿](game-exhibits.md)에 있다. 아래 맵 계약의 기존 이미지/링크 소개 UI에 이 템플릿을 추가한 후속 변경이며 사용자 배포 요청으로 공개 버전 22에 반영했다.

`CampRenderer`는 대표 이미지를 `/games/`의 로컬 자산에서 한 번 로드해 캐시하고 같은 비율로 잘라 부스에 그린다. 실패 시 게임 제목을 남기며 다시 요청하지 않는다. 종료 때 이미지 핸들러·캐시를 정리한다. `game-info-panel.tsx`는 작은 로고/제목 아래에 16:9·최소 높이 200px의 YouTube iframe을 주 콘텐츠로 두고 소개·SNS·출시/관련 링크를 이어 표시한다. `exhibitTrailer`는 기존 YouTube URL 검사로 영상 ID를 추출하고 `youtube-nocookie.com/embed`와 원본 링크를 생성한다. 자동 재생은 지정하지 않으며 팝업을 닫으면 iframe이 제거된다. 공용 라디오 상태·개인 음소거는 변경하지 않는다.

버전 23에서는 사용자 요청에 따라 `cover`를 공식 트레일러의 YouTube 썸네일로 바꿨다. PARRUITS!는 `https://i.ytimg.com/vi/s0pMzMwvKgE/maxresdefault.jpg`의 1280×720 원본을 `/games/parruits-trailer-thumbnail.jpg`로 저장해 사용한다. 기존 로컬 자산 캐시·중앙 자르기·실패 시 제목 표시를 그대로 사용하며 필드 렌더 중 YouTube 이미지 서버에 요청하지 않는다.

`exhibitSocials`가 YouTube·X·Instagram·Discord·Reddit·TikTok의 고정 아이콘 순서와 각 링크를 반환한다. 비어 있거나 공백/잘못된 프로토콜·플랫폼 주소면 `url:null`이며 UI는 href 없는 disabled 버튼·aria-disabled·미등록 안내로 표시한다. 유효한 항목만 새 탭 링크다. 아이콘은 `public/icons/social/`의 로컬 Simple Icons SVG와 CC0 출처 기록을 사용한다. 원격 계정 존재 여부를 매번 검사하거나 미등록 항목에 가짜 주소를 넣지 않는다.

공유 상태·물리·네트워크·DB·통신 규약은 바꾸지 않는다. 기존 근접 상호작용·포커스 잠금·E/Escape·본문 스크롤·닫기 버튼·모바일 라디오 공간 분리를 유지한다. 실제 스트리밍과 분리한 headless 트레일러 fixture로 iframe 위치·URL·종료와 SNS/모바일 UI를 검사한다.

## 맵 확장·포탈·전시장 계약 (v16 도입, 현재 v17)

현재 통신 규약은 **v17**이며 다음은 v16에서 도입한 이동 계약이다. 아래 v15·v13 절은 이전 도입 기록이며 맵 범위·이동 방식은 이 절을 우선한다. `camp-maps.mjs`가 `camp | playground | showroom`의 경계·시설·포탈·부스를 정의한다. 지형 한 변은 12→24타일로 확장했다. 걷기 기준 11.7, 지면 끝 12, 플레이어/공의 상태 범위 14, 투사체 이동 범위 16을 같은 정의에서 참조한다. 낙사·공 복귀·스냅샷 검증·투사체 검증·지형 렌더를 함께 확장했으며 전시장에서도 놀이·들기·던져짐 상태를 거절한다.

`change-map` 명령은 목적지 외에 `portalId`와 현재 `mapRevision`을 필수로 받는다. 방장/솔로의 같은 판정에서 연결·지상·들리지 않음·던져지지 않음·좌석 미점유, 출발 맵의 실제 포탈과 목적지, 1.7 이내 거리·현재 방문 번호를 확인한다. 들고 있는 연쇄는 원래 맵에 안전하게 내려놓고 본인만 옮긴다. 도착 포탈에서 1.9 떨어진 걸을 수 있는 위치에 배치해 도착 즉시 왕복하지 않게 한다. 기존 mapRevision 증가·입력 비우기·이전 방문 입력 거절·중복 명령 처리·500ms 요청 제한은 유지한다. 공중·낙사 중 어디서든 이동하던 예전 계약은 대체한다.

입력 E는 가까운 포탈/게임 부스가 있으면 상호작용하고 그 외에는 기존 통나무/바닥 앉기를 따른다. 화면 상호작용 버튼도 현재 근접 대상을 다시 판정한다. 전체 화면·모바일·필드 PIP에서 같은 필드를 사용한다. 게임 소개를 PIP에서 열면 주 창으로 돌아온다. `game-info-panel.tsx`는 Radix Dialog의 포커스 잠금·Escape/닫기·필드 포커스 복귀를 사용하고, 팝업 동안 게임 입력을 비운다. 소개 팝업은 개인 UI이며 다른 사람의 팝업·방 상태를 변경하지 않는다.

`camp-games.mjs`는 2026-11-05 공식 자료를 확인한 PARRUITS!와 Torizon Telecom의 소개·정보·링크 정적 목록이다. Torizon Telecom은 사용자 후속 배포 요청으로 공개 버전 24에 반영했다. 로고·대표 이미지·게임 장면은 `public/games/`의 공식 자산 사본이며 출처와 권리는 CREDITS.txt에 기록한다. 팝업은 게임별 Steam·데모·공식 웹사이트·SNS·프레스킷 등 등록된 링크를 새 탭으로 제공한다. 자동 크롤링·외부 게임 삽입·게임 등록 DB는 추가하지 않는다. 전시장 채팅 mapId와 플레이어 위치는 전체/변경분·체크포인트·승계에 포함되고 채팅·음악·작업 시간·연결은 기존 방에서 이어진다. DB 마이그레이션은 없다. 공개 배포는 별도 요청이 필요하며 배포 시 모든 참가자가 새로고침해야 한다.

렌더러는 맵 경계에서 바닥·가장자리·산책로를 생성하고 포탈·전시 부스를 그린다. 기본 카메라는 캐릭터를 따라가며 전체 보기에서는 확장한 맵 전체가 들어오게 조정한다. 통나무 집중 보기는 불멍에만 적용한다.

## 방 종료와 새로고침

참여 중인 방의 조회 요청 자체가 401·403·404·410을 반환하면 CampNetwork가 타이머·RTC·페이지 종료 리스너와 미완료 명령을 정리하고 ended를 전달한다. 방 조회 성공 이후 이전 방장 대상 signal이 거절된 경우는 방 종료로 처리하지 않고 다음 조회로 승계를 확인한다. useCampSession은 입장 세대가 일치하는 콜백만 처리하며 종료를 받는 즉시 세대를 증가시켜 중복 종료와 이전 연결의 늦은 상태·채팅·음악·방장 변경을 무시한다. 수동 퇴장의 체크포인트 배출 중 완료된 poll도 종료 알림을 발생시키지 않는다.

화면은 PIP와 입력을 정리하고 URL의 room 초대 코드를 제거한 뒤 location.reload()를 한 번 호출한다. notice=room-ended는 새 로비에서 종료 안내를 한 번 표시한 뒤 제거하며 다른 쿼리·해시는 보존한다. 새 문서에는 방 연결이나 초대 코드가 남지 않아 자동 재입장·반복 새로고침이 발생하지 않는다. 5xx·오프라인·방장 승계·recoveryWaiting은 확정 종료로 취급하지 않고 기존 복구를 유지한다. 서버의 다음 poll 응답에서 종료를 확인한 시점에 동작하며 서버 응답 전 장애 감지를 보장하지 않는다. DB·공유 상태·통신 규약 v15는 변경하지 않는다.

## 시간과 소유권

- 서버의 실제 시각: 참가 만료·방장 임대·정리 주기를 판단한다.
- 각 브라우저의 단조 시각: RTC 수신 확인의 경과 시간·입력 만료·재접속을 판단한다.
- 개인 작업 시간: 이번 입장에서 수동 `working` 상태인 구간을 브라우저의 단조 시각으로 누적한다. 백그라운드 작업도 포함하며, 재연결·방장 변경에는 유지하고 퇴장·페이지 재시작에는 초기화한다. 공유 게임 필드나 영구 통계는 아니다.
- 캠프 시각: 점프·복귀·감정표현·투사체·폭탄·무기 대기시간·음악을 판단한다. 승계 중에는 동결한다.
- 채팅과 호출의 `createdAt`: 방장이 기록한 실제 작성 시각으로 날짜·시간 표시만 담당한다. 기존 `at` 캠프 시각은 호출 대기시간 등에 유지하며 시스템 시각으로 메시지를 재정렬하지 않는다.
- 방장이 물리를 소유한다. React는 렌더링에 필요한 요약만 받는다. 전송 정밀도 조정은 물리 원본에 적용하지 않는다.

## 스냅샷과 복구

스냅샷은 플레이어 필드 목록 하나에서 생성한다. 수신 시 변경 번호·순번·범위·중복 ID·연쇄의 양방향 연결과 순환을 검사한다. 전송 정밀도는 소수점 네 자리이며, 경계 검증에는 그보다 작은 이동을 거절하지 않도록 허용 오차가 있다.

신뢰 채널의 체크포인트는 마지막 채팅 ID와 음악 revision을 포함한다. 해당 상태가 모두 일치할 때만 복구 묶음을 보관하고 수신 확인을 보낸다. 방장도 다른 참가자의 수신 확인을 받은 묶음을 후임 복구에 사용한다. 혼자 있는 방장은 자체 체크포인트를 보관한다. 일반 프레임이 먼저 도착해도 뒤늦은 신뢰 체크포인트의 수신 확인은 처리한다.

승계 시 복구 묶음의 플레이어·축구공·무기·채팅·음악을 함께 되돌리고 입력과 미완료 명령을 비운다. 축구공은 `ball`로 분리하며 고정 전송 형식의 `u` 필드와 체크포인트 기준 변경분에 포함한다. 위치·속도·회전 범위를 검사한 뒤 적용한다. 표시용 참가자 정보가 복구된 물리 좌표를 덮어쓰지 않는다. 새 방장은 첫 체크포인트의 수신 확인 뒤 게임을 재개한다. 마지막 수신 이후 변경의 무손실 복구를 보장하지 않으며, 전원 종료 시 복구 상태도 사라진다.

## 승계 건강 판단

방장 임대는 20초다. 초기 연결 유예 뒤에는 5초 안에 유효한 게임 수신 확인을 받은 참가자가 있어야 갱신한다. HTTP나 RTC 연결 객체만 살아 있는 상태는 충분하지 않다. 일부 참가자만 끊겼을 때에는 다른 참가자의 수신 확인으로 정상 방장을 유지한다.

Worker와 Window 타이머가 실행 기회를 제공하고, 유효한 RTC 입력 수신 시에도 이전 입력의 물리를 먼저 진행한다. 물리는 최대 1초를 1/60초 단위로 보정하며 각 부분 단계의 캠프 시각을 사용한다. 더 긴 정지는 처리하지 못한 캠프 시각을 동결해 분 단위의 낡은 입력을 재생하지 않는다. 250ms 이상 실행 지연이 생기면 5초 동안 방장 갱신과 후임 준비 보고를 중단한다. 지연이 반복되면 기존 임대·복구 절차로 정상 후보에게 승계하고, 후보가 없으면 기다린다. 탭 동결·기기 절전 중 실행은 보장하지 않는다.

환경음의 장작 소리는 반복 오디오 버퍼에 포함해 Window 타이머와 분리한다. 라디오는 문서·플레이어의 가시성이 바뀌어도 앱이 일시정지하지 않는다. 음악용 Document PIP에서는 해당 창에 공식 API를 로드하고, 이동·복귀 시 이전 플레이어를 정리한 뒤 공유 시각에서 새 플레이어를 시작한다. 작은 창은 선택 사항이며 필드 PIP와 음악 PIP는 하나씩 번갈아 사용한다. 브라우저 동결·기기 절전·미디어 자체 제한 중 실행은 보장하지 않는다.

D1은 참가자의 복구 변경 번호·순번·캠프 시각과 확인된 최고 지점을 저장한다. 후임은 같은 복구 변경 번호와 확인 지점에서 5초 이내인 캠프 상태를 가진 활성 참가자 중 입장 순서로 고른다. 실제 시각상의 장애 대기 시간이 길어졌다는 이유로 모든 후보를 탈락시키지 않는다. 후보가 없으면 대기하며 낡은 상태로 자동 초기화하지 않는다.

새 상태가 확인되지 않은 채 세 번 연속 승계되면 여러 참가자 사이의 자동 순환을 멈춘다. 새 체크포인트 확인 시 횟수를 초기화하며, 한 명만 활성인 경우에는 혼자 계속할 수 있다. 이전 변경 번호의 패킷·임대 갱신·시그널은 새 권한을 바꿀 수 없다.

## 성능 기준

### v12 상호작용과 화면 계약

`afkProtected`를 타입·검증·`PLAYER_FIELDS`에서 제거했다. 고정 배열의 필드 위치가 바뀌므로 통신 규약을 v12로 올렸고 이전 버전 패킷은 거절한다. 향후 배포할 때 참가자 전원이 새로고침해야 한다. DB 변경은 없다.

`presence` 명령은 수동 표시 상태·메모·호출 수신만 변경한다. 작업 중·자리 비움이 이동·점프·발사·피격·들기·공 접촉을 차단하거나 자세·연쇄를 강제 정리하지 않는다. 실제 자세·연결·공중 상태와 들리기 동의·탈출은 각각 기존 규칙을 따른다. 낙사 복귀와 승계는 상태·메모·개인 선택·호출 대기시간을 보존한다.

`camp.tsx`가 선택한 패널과 열림 상태를 소유하고 `CampPanel`이 대화·사람·내 상태·놀이를 표시한다. 숨긴 페이지도 마운트를 유지해 작성 중인 메모·채팅과 읽던 위치가 유지된다. 초대는 접힌 영역에 둔다. 760px 이하와 필드 보기에는 고정 하단 메뉴를 제공하며 패널은 필드 위에서 연다. Enter는 대화를 열고 포커스하며 Escape는 필드로 돌아간다. 한글 조합 중 Enter/Escape와 패널의 버튼·입력 포커스는 게임 단축키로 새지 않는다. PIP의 연결 수명은 유지하고 상세 정보는 해당 창에 둔다.

렌더러는 말풍선 배치 후 짧은 상태 배지를 이름표 옆에 배치한다. 캐릭터 몸·프로필·이름표·말풍선·앞서 배치한 배지와 겹치면 추가 배지를 생략한다. 선택한 사람과 본인을 우선하며 배지 클릭도 같은 참가자 상세로 연결한다. 긴 작업·상태 메모는 필드에 그리지 않고 상세 패널에서 읽는다. 밀집된 모든 인원의 표식을 항상 보이는 것은 보장하지 않는다.

이름표는 캐릭터를 그릴 때 변환 행렬·투명도·좌표를 기록하고 맵 오브젝트·효과·비네트를 모두 그린 다음 별도 단계에서 표시한다. 말풍선·집중 보기 대화·상태 배지는 그 뒤에 그린다. 신체의 깊이 순서·지형 가림은 유지하며 표시 대상은 기존 맵/개인 숨김/복귀 중 필터를 따른다. 이름표와 상태 영역의 선택 판정은 모든 신체보다 우선하고 같은 이름표끼리는 기존 그리기 순서를 따른다. DPR·배율·앉기·들린 높이를 기록한 변환과 클릭 영역에 동일하게 적용한다.

### v10 공개방·동석 상태

이 절의 AFK 보호 동작은 도입 당시 기록이며 v12에서 제거됐다.

`camp_rooms.title`, `visibility`는 `0003_true_nextwave.sql`로 추가한다. 기존 방의 기본값은 `unlisted`이며 새 UI는 공개 여부를 명시해서 생성한다. 공개 목록은 인증 전에도 조회할 수 있고 방 코드·이름·인원·정원·입장 상태만 반환한다. 최근 참가자가 없는 방은 제외하고 한 페이지 20개로 제한한다. 목록 조회는 방장 임대를 갱신하거나 승계를 일으키지 않는다. 실제 입장은 기존 세션 검증·원자적 정원 검사를 다시 거친다.

작업 상태와 호출 대기시간은 `PLAYER_FIELDS`에 포함해 전체·변경분·복구에서 함께 전달한다. AFK 보호는 방장 판정과 솔로 시뮬레이션에서 이동·공격·들기·피격 이동을 막는다. 활성화 시 공중·연쇄 상태를 안전하게 정리한다. 앉은 참가자는 들기 양쪽에서 제외하고, 들고 있는 중 앉으면 위쪽 연쇄를 안전하게 내려놓는다. 낙사 복귀와 안전 해제에서도 작업 상태와 호출 대기시간을 보존한다.

호출은 최근 100개 채팅 기록과 같은 복구 스트림에 `kind: call`, `to`, `createdAt`로 보관한다. 송신자 30초·수신자 10초 제한은 플레이어 상태에도 보관하므로 기록에서 오래된 항목이 밀려나거나 방장이 교체되어도 유지된다. 실시간 신규 호출만 알림을 발생시키며 이력·복구는 다시 울리지 않는다. 통신 규약 변경으로 이전 버전 참가자는 새로고침해야 한다.

PIP에는 필드만 React 포털로 옮긴다. 방 연결·솔로 상태·음악은 원래 컴포넌트에 유지한다. 캔버스와 입력은 해당 `ownerDocument`·창을 사용하고 PIP 전환 시 정리·재연결한다. 카메라 배율·추적을 선택·조준 역변환에 함께 적용한다. PIP 닫기는 퇴장이 아니며 원래 창 종료는 PIP와 방 연결 수명에도 영향을 준다.

확대·축소 버튼과 배율 표시를 제거하고 Canvas에만 passive:false wheel 입력을 연결한다. 휠의 pixel/line/page 단위를 정규화해 부드럽게 배율을 변경하고 0.75~3으로 제한한다. Ctrl+휠·비활성/모달 잠금 중 입력은 가로채지 않는다. 채팅·라디오·설정은 Canvas 밖이므로 기존 스크롤을 유지한다. 해제 시 wheel 리스너도 정리하고 PIP에서는 새 ownerDocument의 Canvas에 다시 연결한다. 배율은 같은 React 카메라 상태를 사용하며 전체 보기는 1배와 추적 해제로 돌아간다. Canvas 접근성 안내와 이용 안내에서 휠 조작을 설명한다.

### v9 전송과 복구

게임 데이터와 판정은 참가자 사이의 P2P를 유지한다. 전체 상태는 플레이어 필드 목록 순서의 배열로 전송하고, 수신 확인이 끝난 체크포인트를 기준으로 변경분을 만든다. 같은 기준을 쓰는 참가자끼리는 인코딩 결과를 재사용한다. 일반 프레임끼리 의존하지 않으며 변경분보다 전체가 작거나 유효한 기준이 없으면 전체를 보낸다.

수신 기준 캐시는 표시용 보간 상태와 분리한다. 16개·512KB·10초로 제한하며, 송신은 5초 이내에 발행돼 확인된 기준만 사용한다. 늦은 전체 체크포인트도 캐시에 저장하고 일관된 복구 묶음이면 수신 확인을 보내지만 화면은 과거 순번으로 되돌리지 않는다. 기준을 잃으면 1초에 최대 한 번 재동기화를 요청한다. epoch 변경과 새 연결에서는 이전 기준을 사용하지 않는다.

동작 명령은 즉시 실행·중복 방지·성공/실패 응답을 유지한다. 상태 알림만 다음 33ms 네트워크 틱에서 합쳐 신뢰 채널의 일반 상태로 보낸다. 주기적 전체 복구 체크포인트는 1초마다 유지한다. 전송 전 대기열에서 같은 종류의 상태 알림을 최신 것으로 대체하며 명령 응답·채팅·음악·기록은 FIFO로 보존한다. 이미 RTC에 넘긴 데이터는 취소하지 않는다.

정상 방장 퇴장은 마지막 체크포인트를 전송하고 준비된 참가자의 수신 확인을 최대 1.2초 기다린 뒤 연결을 닫는다. 브라우저 pagehide는 대기하지 않고 최선의 체크포인트 전송과 leave beacon을 시도한다. 강제 종료나 시간 초과에는 마지막 확인 이후 상태가 소실될 수 있다는 기존 한계가 남는다.

적용 코드의 모의 채널 측정에서 v8 비교 기준 대비 상태 배포 데이터량은 전원 대기 61.9%, 16명 이동 입력 84.2%, 16명 무기 조건 78.2% 줄었다. [측정 조건과 한계](p2p-network-benchmark.md#v9-적용-코드-비교)를 함께 확인한다. `npm run test:metrics:p2p`로 재현한다. 실제 회선 업로드·CPU·FPS 개선율은 아니다.

### v8 구조 정리 당시의 모의 비교

동일한 16명 대기 상태와 15Hz 호출을 비교한 모의 측정이다. 실제 인터넷 처리량이나 호스팅 비용 측정은 아니다.

| 항목 | 이전 | 변경 후 |
| --- | --- | --- |
| JSON 스냅샷 | 8,912바이트 | 8,008바이트, 약 10.1% 감소 |
| 10초 대기 전송 프레임 | 150개 | 11개: 일반 1개·신뢰 체크포인트 10개 |
| 정리 작업 사이 일반 참가자 조회 SQL | 12개 | 6개 |

움직임·효과·연결·동작 상태가 달라지면 일반 프레임을 다시 보낸다. 변경이 없어도 신뢰 체크포인트는 1초마다 보낸다. DB 정리는 15초 주기 또는 임대 만료·명시적 퇴장에서 실행한다. 새 복구 지점 보고·방장 갱신·시그널 처리에는 추가 SQL이 필요하므로 모든 요청이 6개라고 해석하지 않는다.

## 검증

`npm test`, `npm run typecheck`, `npm run test:render`, `npm run test:metrics`, 로컬 Worker를 실행한 뒤 `npm run test:network`를 사용한다. 입력 검사는 격리된 EventTarget을 사용하며 사용자 브라우저를 조작하지 않는다. Canvas 직접 렌더링과 Node WebRTC는 실제 브라우저·터치 기기·인터넷 NAT 검사를 대신하지 않는다. 실행과 전체 마이그레이션 절차는 `web/README.md`에서 관리한다.

### 효과음 개인 음량 후속 수정 (2026-11-05)

개인 설정은 effectsVolume(0~1)을 사용한다. 기존 forestVolume은 새 값이 없을 때 이전하며 명시적 0과 음악 음량·음소거를 보존한다. 설정·라디오 탭·팝업은 같은 효과음 값을 즉시 저장/표시하고 저장된 값과 다른 탭의 변경도 오디오에 반영한다. 비동기 AudioContext 재개·녹음 로딩이 UI 갱신을 막거나 늦게 끝난 요청이 최신 값을 덮어쓰지 않는다.

CampAudio의 효과음 master GainNode 아래에 불멍 맵 게이트와 환경음 세기 노드를 둔다. 반복 모닥불과 장작 envelope 모두 master를 통과하므로 이미 재생 중인 장작도 음량·음소거를 따른다. 음소거는 master를 0으로 설정하며 로딩 중 음소거했으면 늦게 준비된 소스를 시작하지 않는다. 음악 플레이어와 공용 상태는 바꾸지 않는다. 게임 전송 규약은 v14를 유지한다.
