# 음성 표시와 모바일 통화 검토

2026-11-04, 공개방·작업 동석 기능 구현에 포함한 기술 검토. 현재 앱의 음성 기능을 추가한 문서가 아니다.

## 확인한 사실

- 현재 `web/lib/camp-api.mjs`는 Discord OAuth의 `identify`만 요청한다. 프로필 사진 연결이며 음성방 참가·음소거·발화 상태를 받지 않는다.
- Discord의 [OAuth2 범위 문서](https://docs.discord.com/developers/topics/oauth2)는 `rpc.voice.read`와 `voice`를 승인된 파트너에게 제공하는 권한으로 설명한다. 일반 프로필 인증에 범위를 추가하는 것만으로 사용할 수 있다고 볼 수 없다.
- [Embedded App SDK 문서](https://docs.discord.com/developers/developer-tools/embedded-app-sdk)의 `VOICE_STATE_UPDATE`, `SPEAKING_START`, `SPEAKING_STOP`은 `rpc.voice.read`를 요구한다. SDK에 이벤트가 있다는 사실과 이 애플리케이션에 사용 권한이 있다는 사실을 구분한다.
- SDK는 Discord Activity 실행 환경과 연동한다. 현재 일반 웹사이트에 그대로 적용된 것으로 간주하지 않는다.

## 대안과 판단

| 대안 | 얻는 경험 | 추가 조건·부담 |
| --- | --- | --- |
| 기존 Discord 통화 사용 | 웹·모바일에서 기존 음성방을 계속 이용 | 앱 안에서 실제 발화·음소거 상태는 확인할 수 없음 |
| Discord Activity 또는 공식 음성 연동 | Discord 실행 흐름과 참가자·음성 정보 연결 가능성 | 앱 권한·플랫폼별 이벤트 지원을 실제 개발자 앱으로 검증해야 함 |
| 자체 웹 음성 | Discord 없이 방 안에서 마이크 사용 | 마이크 권한, 음소거, 장치 변경, 발화 감지, 오디오 전송, TURN와 모바일 복귀 처리 필요 |

자체 음성을 도입한다면 게임 DataChannel과 별도의 오디오 트랙·연결 수명을 설계해야 한다. 게임 방장이 나가도 통화가 이어지는 요구가 있으므로 게임 방장에게 오디오 처리를 단순 종속시키지 않는다. 16명 전체 메시 방식은 총 120개의 참가자 쌍이 되고 각 참가자가 최대 15명에게 송신한다. 이는 연결 수 계산이며 실측 성능이나 운영 비용 예측이 아니다. 서버 중계를 택하면 서버 중심 게임 전환과는 별개로 음성 중계 운영비를 산정해야 한다. 실제 동시 음성 인원·통화 시간·전송률·TURN 이용률이 정해지기 전에는 금액을 확정하지 않는다.

현재 권장안은 기존 Discord 통화를 유지하며 일반 참가자·작업 상태를 먼저 제공하는 것이다. 실제 마이크 정보를 얻지 못한 상태에서 마이크 표시를 추정하거나 수동 상태를 실제 음성 상태처럼 표시하지 않는다.

## 후속 실기기 검증

실제 Discord 개발자 앱과 권한을 확보한 뒤 데스크톱·iOS·Android에서 입장, 음소거, 발화 시작·종료, 채널 이동, 앱 전환, 화면 잠금, 네트워크 전환, 복귀, 방장 교체를 확인한다. 이번에는 문서와 현재 인증 코드만 검토했으며 파트너 권한 승인, 실제 Discord 연결과 모바일 통화를 검증하지 않았다.
