# 장면 구성과 시각 변경의 완료 기준

INT-07의 재발 방지 절차다. 현재 표현·기능의 사용자 결정은 [의도 기준](project-intent.md)을 따른다. 따뜻한 일러스트를 개별 파일로 만드는 것과, 사람·시설·길·카메라·조작 UI가 함께 읽히는 장면을 만드는 것을 각각 검증한다. 구체적인 통나무 각도나 창 크기는 사용자 목적 자체로 고정하지 않는다.

## 적용 범위

자산 교체, 시설·길 배치, 캐릭터 합성, 카메라, UI 크기·위치·표시 조건을 바꿀 때 영향받는 관계를 검토한다. 전면 시각 재구성은 이 문서의 전체 관계를 다룬다. 단일 썸네일 교체는 해당 부스의 합성·가독성만, 문구 오타나 문서 수정은 해당 범위만 확인한다. 일반 작업마다 세 맵·모든 테마·16인 검사를 일괄 실행하지 않는다.

## 제작 전에 정할 것

실제 제작 입력·부분 빌드·검토 명령은 [제작 경로](sprite-authoring.md)를 따른다. 새 작업은 `scene-spec.json`에서 프롬프트·상태 요청·합성 메타데이터를 파생하며, 검토 결과는 같은 작업의 명세·자산·런타임·화면 해시에 연결한다.

이미지를 생성하거나 배치를 바꾸기 전에 다음을 짧게 정리한다. 기존 의도와 코드에서 정할 수 있으면 직접 정하고, 별도의 사용자 승인 단계를 만들지 않는다. 계획만 요청된 경우에는 대화 안에서 정리한다.

- **전달할 장면:** 누가 어디서 무엇을 하는지, 먼저 보여야 할 대상과 보조 정보를 쓴다. 예: 불멍에서는 사람들이 불을 향해 둘러앉고 빈자리·이동 통로를 알아볼 수 있다.
- **공간과 합성:** 바닥 투영, 필요한 시설·몸의 방향, 캐릭터 대비 크기, 바닥·좌면·손 등의 접촉점, 앞뒤 가림을 정한다. 원본 한 장의 좌우 반전으로 필요한 방향을 표현할 수 있는지 확인한다.
- **시야와 동선:** 길의 출발·도착, 시설 접근 공간, 기본·전체·집중 카메라 중 관련 시야와 UI 점유 공간을 확인한다. 길·시설·카메라를 각각의 임의 좌표만으로 끝내지 않는다.

전면 교체는 대표 시설·캐릭터·바닥을 실제 렌더러에 합성한 장면을 먼저 보고 방향·비율을 조정한 뒤 자산 전체로 확장한다. 새로 바뀌는 관계가 없는 작은 수정에는 별도 시제품을 요구하지 않는다.

## 실제 합성 화면에서 확인할 관계

| 관계 | 확인할 것 |
| --- | --- |
| 사람과 시설 | 앉기·들기·무기 등 바뀐 동작의 방향과 접촉점이 시설 그림에 맞는가. 논리 좌석에 앉았는데 몸이 바닥에 있거나 통나무에 묻히지 않는가. 의도한 시선 방향이 읽히는가. |
| 그림과 공간 | 시설·캐릭터의 투영·비율·접지·명암이 함께 놓였을 때 어울리는가. 정면 캐릭터와 등각 바닥의 혼용 자체를 실패로 보지 않고 실제 접촉·가림의 일관성을 본다. |
| 길과 목적지 | 이동 안내로 보이는 길·울타리·표지·포탈이 접근 위치와 실제 목적지 관계를 설명하는가. 장식용 표현이면 이동 안내와 혼동되지 않는가. |
| 맵과 카메라 | 넓은 맵에서도 사람·주요 활동을 찾을 수 있는가. 가까운 화면에서 시설·이름표가 과밀하지 않은가. 빈 공간을 모두 채우거나 승인된 맵 확장을 되돌리는 것을 자동 해결책으로 삼지 않는다. |
| 장면과 UI | 관련 대화 패널·라디오·불 도구·안내를 함께 표시했을 때 사람·활동·접근 경로를 읽을 수 있는가. 빈 상태와 사용 중 상태의 비중이 적절한가. 색뿐 아니라 크기·면적·겹침도 본다. |

대표 장면은 변경 영향으로 고른다. 착석 변경은 불 둘레의 서로 다른 방향과 실제 좌석 점유를, 카메라 변경은 관련 보기 모드를, UI 변경은 실제 패널·오버레이가 열린 상태와 필요한 화면 폭을 확인한다. 기본 배치·일반 진입 상태를 포함하고, 보기 좋게 옮겨 놓은 인공 fixture만으로 통과시키지 않는다. 다크 모드·밀집 인원·PIP 등은 해당 변경에 영향이 있을 때 추가한다.

## 근거와 완료 판단

- **기술 검사:** 추출·프레임·alpha·자산 해시·기능·빌드 결과를 기록한다. PNG 생성 성공이나 PASS 로그는 구도·자연스러움의 증거를 대신하지 않는다.
- **화면 검토:** 생성된 이미지를 실제로 열어 관련 관계를 확인한다. 장면·상태·화면 크기·보기 모드, 이미지 경로, 관찰한 결함과 수정 후 결과를 [검증 기록](validation.md)에 남긴다. Canvas 직접 출력과 전체 UI 캡처를 구분하고, 수정 전 자료를 수정 후 증거로 쓰지 않는다.
- **미해결·미확인:** 승인 범위의 결함은 수정하고 해당 장면을 다시 확인한 뒤 완료로 보고한다. 범위 밖의 결함과 확인할 수 없었던 화면은 따로 남기며 시각 품질 통과로 합치지 않는다. 관련 부분이 미해결·미확인이면 그 부분을 포함한 전면 시각 재구성 완료를 선언하지 않는다. 독립된 승인 작업은 계속한다.

방향·접촉점·표시 영역처럼 명시할 수 있는 관계는 관련 변경 때 의미 있는 회귀 검사로 고정한다. 실제 합성이 어긋나는데 테스트 기대값만 새 출력에 맞춰 통과시키지 않는다. 취향을 임의 점수나 픽셀 일치 임계값으로 고정하지 않는다.

화면 확인은 프로젝트의 computer-use 제한을 따른다. Canvas 직접 렌더와 허용된 격리 headless 자동화로 가능한 근거를 확보한다. 전체 UI를 확인할 수 없으면 소스·Canvas 확인 범위와 미확인 범위를 구분한다. 이 절차는 개인 UI 조작 허가나 상시 사용자 승인 요구가 아니다.

조화를 개선한다는 이유로 승인된 놀이·맵 크기·YouTube 영상·외부 콘텐츠 원색 등을 임의로 없애지 않는다. 하네스 보완과 기존 화면 결함 수정은 별도 상태로 기록한다. 현재 발견된 차이는 [제품 검토](product-review.md)에 둔다.
