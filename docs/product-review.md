[기본 모닥불 근접](../art/sprites/field-night-v1/release/screens/camp-close.png), [이전/야간 비교](../art/sprites/field-night-v1/release/screens/night-comparison.png), 약한 불/강한 불·무광원·노멀 없음·랜턴·다크·혼합 행동·높은 연쇄·Canvas 복구와 PC/모바일/PIP의 **33개 화면**을 검토했다. 기본 진입에서도 불이 밝은 중심으로 읽히고 주변 길과 빈 좌석을 찾을 수 있다. 밤 위에서 읽기 어려웠던 상태·작업 시간 글자는 해당 필드에서만 밝게 보완했다. Canvas는 같은 밤 밝기 관계를 유지하되 노멀 방향 표현은 단순하다.

회귀 중 모의 창 문서의 Canvas 생성 호환성을 수정했고, 테마를 빠뜨린 그림자 마스크 캐시 키를 보완했다. 별도 GPU 픽셀 검사에서 노멀 없는 수광·발광/사진 예외·확대 불변을 확인했다. 같은 초기 마스크 조건의 놀이터·전시장 컬러/다크는 직전 렌더러와 최종 픽셀 차이가 없었다. 미세 GPU 반올림 1단계를 허용하는 검사와 시각 품질 검토는 구분한다.

`field-night-v1`은 로컬 검토·설치본이다. 공유 물리·API·규약 v19·DB와 공개 버전 32를 유지했다. 성능 수치와 검사 근거는 [검증 기록](validation.md)을 따른다. 실물 휴대전화의 성능·발열, 실제 YouTube 음향과 커뮤니티 선호는 확인하지 않았다.

**후속 공개 결과:** 2026-11-06 사용자 **“스프라이트 윤곽 사용 수정본을 배포해줘”** 요청으로 아래 `field-shadow-v4` 검증본을 기존 사이트 **버전 32·규약 v19**에 반영했다. 30개 검토와 현재 소스·자산의 일치를 다시 검사하고 새 공식 빌드를 배포했으며, 공개 파일 84개와 API를 확인했다. 아래 로컬 표기는 수정 당시의 이력이다. public 접근·DB·환경 리비전 1을 유지했고 상세 근거는 [검증 기록](validation.md)에 남겼다.

## INT-19 후속 · 그림자 농도 재조정 (2026-11-06, 로컬)

사용자가 v3 전후 비교에서 수정 후 그림자가 거의 보이지 않는다고 지적했다. **v3의 기본 장면 명암 가독성 판단을 정정한다.** 형상·광원·합성 순서 수정은 유지하되, 투영의 제곱 거리 감쇠와 낮은 계수를 조정하고 발/다리 접촉을 강화했다. 중간 거리 예시의 최종 농도는 약 4.5%에서 18%로 바뀐다. 이는 모든 픽셀의 고정 불투명도가 아니라 광원 거리·세기에 따른 계산 예시다.

`field-shadow-v4`의 [기본 모닥불 근접 화면](../art/sprites/field-shadow-v4/release/screens/camp-close.png)과 [농도 비교](../art/sprites/field-shadow-v4/release/screens/shadow-contrast-comparison.png)를 열어, 벤치 뒤의 짧은 투영과 발·다리 밑 접촉이 바닥에서 구분되는지 확인했다. 길이·윤곽·지면 패스는 바꾸지 않았다. 기본 전체 보기·다크·랜턴·밀집 행동·Canvas와 실제 PC/모바일/PIP도 새 [30개 검토](../art/sprites/field-shadow-v4/release/review.json)에 연결했다. 공개 버전은 31이며 이번 농도 변경은 로컬 검증본이다.

## INT-19 후속 · 그림자 수정 검토 (2026-11-06, 로컬)

사용자가 원인 분석 후 수정을 요청했다. 긴 타원 투영을 색 원화 alpha와 실제 몸 합성의 윤곽으로 교체하고, 원화 다리의 접촉 구간을 사용한다. 시설 크기·방향과 착석 보정은 색상 렌더와 같은 기하를 공유한다. 고정 우하향 그림자를 제거하고 모닥불·랜턴·진단광을 같은 입력으로 전달하며, 정적/캐릭터 그림자 모두 지면 패스에서 그린다.

[최종 근접 화면](../art/sprites/field-shadow-v3/release/screens/camp-close.png)과 [이전/수정 비교](../art/sprites/field-shadow-v3/release/screens/shadow-comparison.png)에서 앞 벤치 아래의 길고 가는 얼룩 제거, 다리 밑 접촉과 빈 공간을 확인했다. 좌/우 세계 광원 이동에 표면과 그림자가 함께 반응하고, 무광원에는 접촉만 남으며 랜턴도 반대 방향 투영을 만든다. 세 맵·16명/혼합 행동/높은 업기·Canvas 복구·실제 PC/모바일/PIP 등 [30개 검토](../art/sprites/field-shadow-v3/release/review.json)를 새 fingerprint에 연결했다. 이전 검토 묶음을 새 결과로 덮어쓰지 않았다.

마스크 생성은 새 동작에서만 수행하고 캐릭터는 절반 해상도로 캐시한다. 기존 색/노멀 PNG 27개와 원형 사진·공식 게임 미디어는 유지한다. 이는 alpha/접촉선을 이용한 2.5D 근사이며 정확한 3D 복원이나 커뮤니티 선호 보장은 아니다. 실물 휴대전화 성능은 미확인이고 측정 비용은 [검증 기록](validation.md)에 남긴다. 아래 미해결 절은 수정 전 진단 기록이며, 이번 수정은 로컬 결과로 공개 버전 31과 구분한다.

## INT-19 후속 · 그림자 자연스러움 재검토 (2026-11-06, 미해결)

사용자가 공개 후 그림자가 이상하다고 지적했다. 정식 검토본의 `camp-close`, `camp-color`, `actions`, `ui-mobile-field`를 다시 열고 생성·합성·진단광 코드를 대조했다. 앞쪽 벤치 뒤의 길고 흐린 자국이 사물의 투영 형태로 읽히지 않는다. **아래 최초 검토의 그림자 자연스러움 pass 판단을 철회한다.** 당시 PNG·review는 배포 이력으로 보존하며 기술 검사·파일 정합성 통과와 현재 미해결 품질을 구분한다.

| 확인한 원인 | 코드 근거와 영향 |
| --- | --- |
| 투영 형태를 긴 타원 하나로 대체 | `GroundShadows.cast`는 벤치의 축·다리/상판 형상을 유지하지 않고 공통 타원을 광선 방향으로 회전·확대한다. 타원의 중심은 길이의 .48, 긴 반경은 최소 길이의 .7이므로 접촉점 앞쪽까지 번진다. 벤치 밑이 긴 얼룩처럼 보이는 직접 원인이다. |
| 표시 광원과 그림자의 기준이 다름 | 정적 사물에 접촉·고정 우하향·모닥불 투영을 겹친다. 랜턴은 표면 조명/빛 번짐에 참여하지만 투영은 `kind==='fire'`만 처리한다. 광원별 밝기·그림자 관계가 일관되지 않다. |
| 캐릭터 그림자를 지면 패스로 분리하지 않음 | 정적 그림자는 사물 이전에 그리지만 캐릭터 그림자는 깊이 정렬 루프의 `player()` 안에서 그린다. 앞서 그린 벤치·다른 사물에 바닥 그림자가 덧칠될 수 있는 구조다. 현재 모든 캐릭터 겹침에서 발생했다고 단정하지 않는다. |
| 진단광 검토가 그림자까지 움직이지 않음 | `lighting-preview.mjs`의 좌/우 진단광은 명령 기록 뒤 WebGL `frame.lights`만 바꾼다. 그림자·바닥 번짐은 기존 `renderer.lights`로 먼저 그려진다. 이전 좌/우 비교는 노멀 반응 근거이며 조명/그림자 일관성의 근거로 쓸 수 없다. |

기존 검사는 유한값·길이 상한·캐시·차폐·backend를 확인하지만 그림자의 사물별 형태·접촉점·광원 이동·수신 표면·가림 관계를 충분히 검증하지 않았다. 이 사실과 실제 화면의 결함을 이전에 직접 열람하고도 충분히 구분하지 못했다. 수정 방향은 사물 바닥 형상과 접촉점에서 시작하는 투영, 공통 광원 입력, 지면 그림자 패스 분리, 같은 장면의 조명/그림자 동시 이동 검토다. 이 절은 원인 분석 기록이며 수정 완료를 의미하지 않는다.

INT-17 후속 배포: 사용자 “배포해줘” 승인으로 동일 검증본을 기존 사이트 **버전 28·규약 v18**에 공개했다. 아래 초기 검토의 배포 제외 경계는 이 후속 승인으로 대체한다. 공개 파일/API 확인은 [검증 기록](validation.md)을 따른다.

## 후속 검토: 제작 경로 구현과 실제 파일럿 (2026-11-05)

승인한 계획에 따라 [제작 경로](sprite-authoring.md)를 구현했다. 명세에서 작업별 프롬프트/요청을 만들고, 선택 원본만 공식 sprite-gen으로 처리하며, 독립 자산 context를 실제 renderer와 격리 UI에 연결한다. 방향·좌면·지면 접촉과 깊이 정보가 표시 코드에 적용된다. 기존 공개 자산·물리·규약은 유지했다.

내장 image_gen으로 파일럿 원본 5개를 만들고 세 맵·서로 다른 축의 착석·실제 PC/모바일 UI를 확인했다. 오접촉점과 지형 셀 크기 결함을 실제 화면에서 발견하고 수정 후 확인했다. 그러나 정면 앉기의 시선, 나머지 통나무 방향, 동선·밀도·빈 라디오와 패널의 점유는 여전히 남아 있다. 이 파일럿은 기술 경로 검증이며 전체 시각 재구성 성공 사례가 아니다. [검토 스냅샷](../art/sprites/pilot-source/pilot-review.json)에 실패 관찰과 부분 통과를 구분했다. 실제 `verifyReview`는 실패한 장면을 거절해 전체 신규 생성 준비를 허용하지 않았다.

이번 구현은 반복 실수를 발견하고 다음 제작으로 넘기지 않는 경로를 갖추는 범위다. 아래 장면 불일치를 고쳤다고 대체하지 않는다. 기본 명세도 5개 파일럿의 범위이며 전면 재생성 때는 전체 자산/장면 범위를 먼저 명세에 추가해 대표 부분을 다시 검토해야 한다. 독립 에이전트 실행이나 미감의 자동 보증으로 보고하지 않는다.

## 후속 검토: 장면 구성의 불일치와 재발 방지 (2026-11-05)

사용자가 배치·주변 사물의 조화·눈으로 보이는 의도가 어색하다고 지적했다. 현재 코드와 재생성한 Canvas 출력, 기존 전체 UI 캡처에서 다음 차이를 관찰했다. INT-17의 자산 제작·기능 검증 사실은 유지하되, 그것만으로 같은 공간의 시각 언어가 완성됐다고 판단하지 않는다.

| 관찰한 차이 | 현재 상태 |
| --- | --- |
| 좌석은 8방향으로 배치하지만 통나무 그림은 한 장을 좌우 반전한다. 앉기 그림에는 시선 방향이 반영되지 않고 앞쪽 통나무가 몸을 가린다. | 미해결. 좌석·그림의 방향·접촉·가림을 함께 맞춰야 한다. |
| 길은 시설·포탈 좌표와 별도로 그려진 곡선이며 진입점에 연결되지 않는다. | 미해결. 안내로 보이는 길과 실제 접근 동선을 대조해야 한다. |
| 전체 보기에서는 중앙 활동이 작고 주변이 비어 보이며 가까운 보기에서는 안내·시설이 밀집한다. | 미해결. 승인된 맵 확장은 유지하며 활동 배치와 카메라를 함께 검토해야 한다. |
| 기존 UI 캡처에서 대화 패널·빈 라디오·불 성장 카드가 장면과 시선을 나눠 가진다. | 미해결. 실제 UI 점유 공간과 빈 상태의 비중을 검토해야 한다. 이번에 브라우저 캡처를 새로 생성한 것은 아니다. |

후속 재발 방지 요청에 따라 [장면 구성 기준](scene-composition.md)을 AGENTS와 제작·제품 검토·변경 검증 스킬에 연결했다. 생성 전에 공간 관계를 정하고 대표 합성 장면을 먼저 확인하며, 화면을 열어 본 근거와 미해결을 구분하도록 했다. **절차 보완은 기존 장면 결함의 수정 완료가 아니다.** 이번 하네스 작업에서 게임 코드·자산·배치는 변경하지 않았다. 실제 실행과 절차 점검의 한계는 [검증 기록](validation.md)에 남긴다.

## 후속 검토: 일러스트 전면 교체 (2026-11-05, INT-17)

이 절은 INT-17 구현 당시의 검토다. 이후 확인된 장면 구성의 차이는 위 후속 검토를 따른다. 캐릭터·환경·효과를 실제 생성 PNG로 교체하고 sprite-gen의 추출/합성/분할/타일 경로를 연결했다. 로비와 필드 패널도 그림 미리보기·입장 카드·따뜻한 표면으로 재구성했다. 앱 안에 생성 도구를 넣거나 장식 몇 개만 교체한 상태로 완료 처리하지 않는다. 다만 SEED의 접근성/상태 컴포넌트, 게임/방/채팅/라디오의 기능 코드는 유지한다.

쉬며 곁에 있기에는 새 모닥불·좌석·사진 머리, 함께 놀기에는 16상태의 몸동작·장난감·연쇄, 작업 중 왕래에는 개인 상태·PIP·복원, 게임 소개에는 공식 썸네일/트레일러와 새 부스가 대응한다. 들기 탑에서 새 몸 크기가 하단 얼굴 선택을 가리는 문제를 찾아 간격과 규약을 함께 수정했다. 재생성 도중 발생한 도구 성능 문제는 정확 RGB lookup 앱 어댑터로 해결하고 공식 recolor와 구분해 문서화했다.

추출 검사는 자연스러운 동작의 충분조건이 아니다. 짧은 생성 pose loop, 상하체 clipping과 손 crop은 Canvas 프레임/격리 브라우저의 확인 범위이며 실제 커뮤니티의 캐릭터 선호와 실기기 체감은 확인하지 않았다. 소스 PNG가 추가되어 전송량과 CPU 렌더 비용도 증가했으며 수치는 검증 기록에 남긴다. 이번 요청은 구현·검증으로 한정하며 공개 배포·원격 저장소 변경은 하지 않는다.

## 후속 검토: 컬러·다크 모드 (2026-11-05, INT-16)

사용자가 칙칙한 색감을 지적하고 두 모드를 설정에서 선택하는 계획을 승인했다. 현재 소스는 기본 컬러 모드의 따뜻한 불꽃·자연색 지형·색상별 캐릭터와 기존 흑백 다크 모드를 제공한다. SEED 화면 구조와 포탈/번호/형태 표식은 유지하고, 외부 이미지·영상 원색을 보존한다. 이 결정이 INT-14·15의 흑백 고정 기준을 대체한다.

검토 범위는 로비에서 선택·저장→입장 후 전환→필드/음악 PIP→재접속 복원이다. 소리와 들기 동의·대화 초안·방 데이터는 테마 선택과 분리하며 새로운 운영 기능이나 게임 규칙을 추가하지 않았다. Canvas 직접 렌더와 격리 브라우저 스크린샷은 기술·시각 근거이며 실제 커뮤니티의 색상 선호와 실기기 만족도는 검증하지 않았다. 추가 사용자 결정 없이 승인 범위를 구현했다. 후속 배포 요청으로 동일 검증본을 공개 버전 27·규약 v17에 반영했다. 공개 파일 일치 확인 등 실행 근거는 검증 기록에 둔다.


## 후속 검토: 기존 시각 계층 철회와 SEED 재구축 (2026-11-05, INT-15)

사용자는 이전 결과가 색상 변경 중심이라는 점을 지적하고 전면 재구축을 다시 승인했다. 이전 기록의 “전체 재구성” 완료 해석을 정정한다. 기존 UI 소스/스타일과 필드 그림을 제거하고, 공식 스니펫·SEED Tabs/BottomSheet/Dialog/List/Select를 실제 입장·대화·사람·상태·놀이·라디오 흐름에 연결했다. 새 로비는 준비와 공간 선택을 나누며 생성·코드 입장은 대화상자에서 진행한다. 필드는 새 기하형 그림과 외곽 장식 배치로 다시 구성했다.

초안/읽던 위치·공유 채팅·라디오·개인 음량·좌석/불 성장·포탈·전시 콘텐츠·PIP의 기존 의미를 보존한다. 검토 중 모바일 닫힌 패널의 가림, 입력창 높이 고정, 소개창 스크롤 후 닫기 버튼, 영상과 필드 조작 겹침을 발견해 수정했다. 기능을 유지한다는 판단은 로컬 기술 검사 근거이며 실제 커뮤니티의 분위기 선호나 실물 모바일 키보드 사용 만족도를 검증한 것은 아니다. 초기 범위는 구현·검증이었다. 이후 사용자 “배포해줘” 요청으로 같은 검증본을 기존 사이트 버전 26·규약 v17에 공개했다. 공개 파일/API 일치 확인은 검증 기록에 둔다.

## 이전 부분 전환 검토: SEED와 블랙앤화이트 (2026-11-05, INT-14)

사용자가 전체 UI와 게임 필드의 흑백 재구성을 확정하고 구현·검증을 승인했다. 기존 색상 표현은 이번 결정으로 대체한다. 로비·입장·대화·사람·수동 상태·놀이·라디오·소개·퇴장 흐름의 기능을 유지하며 조작 컴포넌트를 SEED로 전환했다. 표식이 있는 포탈·여섯 캐릭터 명도와 번호·형태가 다른 불 해금으로 색 이외의 단서를 제공한다. 외부 게임·프로필·영상은 원색을 유지한다.

확인 범위는 Canvas 렌더와 로컬 격리 브라우저의 실제 흐름이며, 스크린샷 검사 중 발견한 SEED flex 기본값·position·팝업 쌓임 충돌을 수정했다. 조용한 동석·대화와 놀이·개발 중 동행·게임 소개를 기능적으로 이어가고, 흑백 분위기의 실제 커뮤니티 선호는 사용자 사용 결과로 확인할 사항이다. 새 운영 기능이나 게임 규칙을 추가하지 않았으며 이번 작업은 공개 배포를 포함하지 않는다. 상세 검사 결과는 검증 기록에 둔다.

2026-11-04부터의 검토 이력. [의도 기준](project-intent.md)에 비춰 구현과 다음 결정을 분리한다. 첫 표는 하네스 정리 당시의 상태이며, 이후 구현 결과는 문서 아래 후속 검토를 우선한다. **최신 표현 결정은 컬러·다크 선택(INT-16)이고 SEED 전면 재구축(INT-15) 구조를 유지하며, 공통 전시 부스·대표 이미지·트레일러 중심 소개와 미등록 SNS 비활성 표시(INT-13)는 유지한다. 맵 확장·포탈 이동(INT-08·12), 기존 모닥불·Discord 입장·상태 보호 제거와 연결 유지 기준은 이어진다. 관리 기능은 보류이며 게임 소개 기능의 과거 보류는 승인 범위에서 대체됐다.**

## 검증 해석

이전 구현의 자동 검증과 공개 배포 기록은 [검증 문서](validation.md)에 남아 있다. 이번 작업은 규칙·문서·스킬에 한정하므로 스킬 형식, 참조 경로, 적용 범위와 질문·승인 경계를 확인한다. 이전 테스트 통과를 이번 실행 결과로 재기록하지 않는다.

실제 커뮤니티에서 네 장면이 편안하게 공존하는지, 처음 온 사람이 설명 없이 구역을 이해하는지는 아직 확인하지 않았다. 루프백 WebRTC는 인터넷 NAT·모바일 연결을, Canvas 직접 렌더는 전체 브라우저 UI와 입력 경험을 보증하지 않는다.

다음 제품 설계에서 먼저 필요한 결정은 **휴식/놀이 공간이 같은 캠프에서 어떻게 연결되는가**이다. 이 선택 뒤에 공간별 상호작용 사례를 구체화한다.

## P2P 전송 개선 후속 검토 (2026-11-04)

사용자가 P2P 유지를 명확히 한 뒤 전송 최적화·검증·배포를 승인했다. v9는 방장과 참가자 사이의 전송 형식과 발행을 바꾸며 공간 구성·장난 규칙·개인 휴식 선택은 바꾸지 않았다. 정상 퇴장 시 마지막 상태를 이어주도록 수신 확인 대기를 보완했다. 99개 검사와 16명 루프백 RTC의 장애·승계 검증을 통과했으며 공개 사이트 버전 10으로 배포했다. 성능 근거는 [적용 코드 비교](p2p-network-benchmark.md#v9-적용-코드-비교)에 둔다.

방장의 회선 부담을 줄이는 방향은 제품 의도에 맞지만, 실제 커뮤니티에서 더 편안해졌다는 사용 결과까지 확인한 것은 아니다. 앞선 휴식/놀이 공간·작업 중 동석·게임 소개 관련 미정 사항은 여전히 후속 제품 결정이다. 방장 퇴장 확인창의 오래된 안내 역시 이번 통신 작업에서 변경한 것으로 간주하지 않는다.

## 공개방과 작업 동석 구현 후속 검토 (2026-11-04)

사용자가 승인한 계획에 따라 공개방 목록, 링크 참가 화면, 실제 승계에 맞는 퇴장 안내를 구현했다. 기존 방은 목록에 자동 공개하지 않고 새 방은 생성 시 공개 범위를 선택한다. 방 발견은 서버의 로비 정보로 제공하며 게임의 P2P 전송·판정은 유지한다. 누구나 참여하는 공개 목록이며 Discord 커뮤니티 회원 인증은 포함하지 않는다.

작업 메모·수동 상태·AFK 보호/장난 허용·호출 수신 선택과 날짜·시간 기록을 추가했다. 게임 입력이 없는 개발 작업을 자동 자리 비움으로 오해하지 않도록 상태는 수동으로 정한다. AFK 보호는 피격 이동과 들기를 실제 방장 판정에서 차단하고 자기 이동·공격도 막는다. 앉기와 들기를 함께 쓰지 않도록 규칙을 맞추고, 주요 통로의 통나무·텐트를 옮겼으며 앞쪽 장식이 캐릭터를 가릴 때 투명도를 낮춘다.

필드 보기·줌·자기 캐릭터 추적·지원 환경의 Document PIP를 구현했다. 작은 창에는 필드와 참가자 목록을 두고, 상태 편집·채팅은 원래 화면에서 이어간다. 선택한 친구의 상세 정보와 호출은 작은 창에서도 사용한다. PIP를 닫아도 방 연결은 유지한다. 작은 창은 원래 웹 창의 수명에 종속되며 독립 바탕화면 앱은 아니다.

기술 검증 중 방장 승계에서 데이터 채널이 제어 채널보다 먼저 열리면 복구한 참가자를 끊김으로 표시해 들기 연쇄를 해제할 수 있는 경합을 확인했다. 기존 복구 상태를 제어 핸드셰이크 이전에 해제하지 않도록 고치고, 이전 채널의 늦은 콜백도 현재 연결에 적용되지 않게 했다. 해당 순서를 재현하는 회귀 검사를 추가했다.

이번 변경은 ‘개발 중 곁에 머물기’를 직접 돕는다. 휴식/놀이 구역과 경계 규칙은 여전히 미구현이며 개인 AFK 보호로 대체됐다고 보지 않는다. 많은 인원의 긴 메모는 필드에서 줄이거나 겹침을 생략하고 상세 정보에서 읽게 한다. 실제 커뮤니티에서 가독성과 호출 빈도가 편안한지는 후속 사용으로 확인해야 한다. 음성 상태·모바일 통화는 [기술 검토](voice-options.md)에 권한 조건과 미검증 범위를 남겼다. 실행 증거와 공개 배포 여부는 [검증 기록](validation.md)을 따른다.

## 축구공과 작업 동석 보강 (2026-11-04, 규약 v11)

승인된 다섯 항목을 기존 흐름에 연결했다. 축구공은 걸어서 밀고 달려서 더 세게 차며 방장 판정과 복구 묶음을 공유한다. 점수·팀전·다른 플레이어를 공으로 밀어내는 효과는 추가하지 않았다. 모닥불과 통로를 피한 초기 위치를 사용하지만 휴식 구역 보호를 구현한 것은 아니다.

채팅은 오래된 메시지부터 아래로 쌓고 날짜 구분도 같은 방향으로 표시한다. 하단에서는 새 메시지를 따라가고 과거 대화를 읽는 동안에는 최신 이동 버튼을 제공한다. 작업 상태는 기존 수동 계약을 유지하면서 빠른 선택과 참가자 목록 표시를 보강했다. 본인 작업 시간은 이번 입장의 작업 상태 구간만 누적하므로 다른 창에서 개발하는 시간도 포함한다. 재연결·방장 변경은 시간을 초기화하지 않고 페이지 재시작이나 퇴장은 새 세션으로 취급한다.

사용자가 선택한 YouTube 작은 창은 보이는 공식 플레이어를 유지하는 Document PIP다. 기존 필드 PIP와 번갈아 사용하며 작은 창을 닫으면 같은 방의 공유 시각에서 원래 화면에 재생을 복원한다. 전환 중 플레이어를 다시 생성하므로 무중단 음향을 약속하지 않는다. 미지원 브라우저는 보이는 원래 플레이어를 사용한다. 환경음은 오디오 버퍼에서 반복하며, 게임은 Worker 실행 기회·지연 보정·건강 기반 승계를 함께 사용한다. 기기 절전과 모든 참가자의 탭 동결 중 계속 실행되는 서버형 월드로 바뀐 것은 아니다.

123개 회귀 검사, 타입·빌드·Canvas, 16명 루프백 RTC와 격리된 헤드리스 PIP 검사는 기술 근거다. YouTube 재생 API는 브라우저 검사에서 대체했으므로 실제 곡의 광고·자동재생·청취와 실물 모바일 절전은 미검증이다. 공개 배포와 커뮤니티 사용 결과는 이번 로컬 구현 결과와 구분한다.

## 전체 프로젝트 피드백 (2026-11-04)

> 후속 결정: 아래 보호 관련 가치 판단·우선순위는 AI 제안으로, 사용자 답변 후 철회했다. 사용자는 작업 중·자리 비움에도 상호작용하기를 원하며 보호 기능 제거를 승인했다. 화면·상태 표식 개선은 승인, 공개방 관리·게임 소개 확장은 보류했다. 아래 내용은 당시 관찰·제안의 이력으로만 보존한다.

사용자의 전체 피드백 요청으로 현재 작업 폴더의 제품 기준, UI, 물리·상태 계약, 연결·복구, API·DB, 테스트와 기존 화면 산출물을 검토했다. 아래는 검토자의 평가와 후속 제안이며 새 기능의 구현 승인이나 제품 방향 변경이 아니다. 게임 코드는 변경하지 않았다. 이번 실행 근거는 [검증 기록](validation.md#2026-11-04-전체-프로젝트-피드백-검증)에 둔다.

### 종합 평가와 강점

핵심 놀이와 기술 기반을 갖춘 커뮤니티 알파로 평가한다. 다음 우선순위는 휴식과 놀이가 공존하는 규칙, 처음 온 사람의 화면 이해, 서로 다른 환경에서 오래 머무는 경험이다. 실제 이용자의 재방문과 편안함을 확인한 자료는 아직 없다.

- 숲·불빛·색상·캐릭터가 일관되고, 게스트·공개방·초대 링크·혼자 둘러보기로 입장 경로를 제공한다.
- 체력 경쟁 없이 축구공·연쇄 들기·감정표현 등 함께 반응할 소재가 있으며, 작업 상태·메모·개인 작업 시간·PIP는 개발자 동석이라는 목적에 직접 연결된다.
- 개인 듣기와 공유 재생을 분리하고, 들리기 동의·탈출·AFK 보호를 판정에 연결했다. 상태를 자동 AFK로 바꾸지 않는 점도 다른 창에서 개발하는 사용 방식과 맞는다.
- 명령 중복 방지, 입력 잠금, 일관된 체크포인트, 이전 방장 권한 거절, 재접속과 승계의 회귀 검사가 있다. 기존 퇴장 안내 불일치와 작업 동석 기능 부재는 해결된 항목으로 취급한다.

### 기술·운영 피드백

- **실제 장시간 이용 검증:** 기존 16명 루프백과 격리 브라우저 검사는 좋은 기술 근거다. 다음에는 서로 다른 회선, 실제 TURN 경로, 주 창 최소화와 PIP, 방장 이탈, 실제 YouTube 재생을 포함한 모임으로 입장 성공과 복구 시간을 확인해야 한다. 모든 기기가 잠들었을 때 실행을 유지하는 것은 현재 구조의 보장 범위 밖이다. P2P 유지는 확정 방향이다.
- **서버 부하도 별도로 측정:** `CampNetwork.poll`은 안정 상태에서도 응답 후 3초마다 API를 조회한다. 응답 시간을 제외한 계산상 16명은 시간당 약 19,200회이며, 이는 관측된 처리량이나 비용이 아니다. P2P 게임 전송량 감소와 HTTP·D1 부하는 분리해서 평가해야 한다.
- **변경하기 쉬운 구조:** 물리·전송·복구의 모듈 경계와 테스트를 유지한다. `camp.tsx`에는 화면 구성 외에 솔로 명령·입력·프로필 인증·작업 시간의 수명 관리가 함께 있고, 일부 JSX·CSS가 긴 한 줄로 압축돼 있다. 다음 관련 수정에서 읽기 좋게 정리하고 수명 관리를 나누는 편이 좋다. `@ts-check` 적용은 부분적이며 타입 검사 통과가 모든 `.mjs`의 엄격한 검사를 뜻하지 않는다. 전면 재작성은 제안하지 않는다.
- **문서의 현재 상태 정리:** 루트 README는 배포 버전 11과 채팅 최신순을 안내하지만 검증 기록의 마지막 배포는 버전 12이고 현재 채팅은 오래된 것부터 쌓인다. `web/README.md`의 ‘현재 작업 폴더에 이미 적용’이라는 설명과 달리 기본 `.wrangler/state` DB의 `camp_rooms`에는 `title`, `visibility`가 없다. 해당 DB로 실행하면 공개방 조회·생성이 실패할 수 있으므로 현재 스키마를 확인한 뒤 누락 마이그레이션만 적용하도록 안내를 고쳐야 한다. 이번에는 읽기 전용 스키마 확인만 했으며 SQL을 적용하지 않았다.

### 제안하는 다음 순서와 완료 기준

1. 현재 실행 안내·배포 설명을 맞추고, 휴식/놀이 공간 관계와 경계 사례를 정한다. 쉬는 사람 보호와 이미 승인된 놀이가 함께 성립해야 한다.
2. 사람·상태·채팅의 화면 우선순위와 밀집 장면의 라벨을 정리한다. 처음 온 사람이 별도 설명 없이 친구를 찾고, 앉고, 상태를 바꾸고, 채팅한 뒤 필드로 돌아올 수 있는지 본다.
3. 소규모 커뮤니티에서 서로 다른 회선으로 30~60분 함께 사용한다. 참가 성공률, 복구 시간, 원치 않은 방해, 채팅 접근, 다시 방문하려는 이유를 확인한다. 공개 운영의 최소 관리 수단도 이 단계에서 점검한다.
4. 게임 소개는 실제 이용에서 나온 필요에 맞춰 작은 기능부터 확장한다. 상설방·회원 제한·음성 도입은 미정 사항으로 남긴다.

화면 평가는 기존 헤드리스 브라우저 캡처 2개와 Canvas 직접 렌더 1개를 읽은 결과다. 이번에 브라우저·개인 데스크톱을 조작하거나 새 화면 캡처·배포·실인터넷 통신 검사를 수행하지 않았다. 실제 사용성의 확정 결론과 구분한다.

## 라디오 자동 재생과 개인 음소거 (2026-11-05)

- 상시 플레이어가 데스크톱 채팅과 모바일 메뉴·이동 조작을 가리지 않도록 배치를 조정했다. 라디오 근처 버튼은 ‘라디오 설정’으로 표시하며 신청곡과 방장 제어에 사용한다.
