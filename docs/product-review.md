# 제품 의도와 현재 구현 검토

2026-11-04의 검토 이력. [의도 기준](project-intent.md)에 비춰 구현과 다음 결정을 분리한다. 첫 표는 하네스 정리 당시의 상태이며, 이후 구현 결과는 문서 아래 후속 검토를 우선한다. **최신 결정은 통나무 불멍·개인 숨김·라디오 탭(INT-09)과 Discord 필수 입장(INT-10)이다. 별도 불멍·놀이터 맵(INT-08), 상태 보호 제거·화면 접근과 가독성 개선을 유지한다. 관리·게임 소개 기능은 보류다. 과거의 보호 확대와 공간 설계 우선 제안은 현재 실행 기준이 아니다.**

## 검토 범위와 구조

자체 앱의 입장→머물기→상호작용→연결 복구→퇴장 흐름과 테스트를 검토했다. UI와 핵심 규칙을 직접 읽고 관련 참조·테스트를 추적했다. 의존 패키지, 생성된 배포 산출물과 모든 줄에 대한 정밀 감사는 포함하지 않는다.

| 영역 | 확인한 코드 | 제품에 미치는 의미 |
| --- | --- | --- |
| 입장과 프로필 | `camp-lobby.tsx`, `use-camp-session.ts`, `camp-api.mjs`, `camp-discord.mjs` | 방 생성과 코드 입력이 함께 보임. Discord 연결 없이 참여 가능 |

## 검증 해석

이전 구현의 자동 검증과 공개 배포 기록은 [검증 문서](validation.md)에 남아 있다. 이번 작업은 규칙·문서·스킬에 한정하므로 스킬 형식, 참조 경로, 적용 범위와 질문·승인 경계를 확인한다. 이전 테스트 통과를 이번 실행 결과로 재기록하지 않는다.

실제 커뮤니티에서 네 장면이 편안하게 공존하는지, 처음 온 사람이 설명 없이 구역을 이해하는지는 아직 확인하지 않았다. 루프백 WebRTC는 인터넷 NAT·모바일 연결을, Canvas 직접 렌더는 전체 브라우저 UI와 입력 경험을 보증하지 않는다.

다음 제품 설계에서 먼저 필요한 결정은 **휴식/놀이 공간이 같은 캠프에서 어떻게 연결되는가**이다. 이 선택 뒤에 공간별 상호작용 사례를 구체화한다.

## P2P 전송 개선 후속 검토 (2026-11-04)

사용자가 P2P 유지를 명확히 한 뒤 전송 최적화·검증·배포를 승인했다. v9는 방장과 참가자 사이의 전송 형식과 발행을 바꾸며 공간 구성·장난 규칙·개인 휴식 선택은 바꾸지 않았다. 정상 퇴장 시 마지막 상태를 이어주도록 수신 확인 대기를 보완했다. 99개 검사와 16명 루프백 RTC의 장애·승계 검증을 통과했으며 공개 사이트 버전 10으로 배포했다. 성능 근거는 [적용 코드 비교](p2p-network-benchmark.md#v9-적용-코드-비교)에 둔다.

방장의 회선 부담을 줄이는 방향은 제품 의도에 맞지만, 실제 커뮤니티에서 더 편안해졌다는 사용 결과까지 확인한 것은 아니다. 앞선 휴식/놀이 공간·작업 중 동석·게임 소개 관련 미정 사항은 여전히 후속 제품 결정이다. 방장 퇴장 확인창의 오래된 안내 역시 이번 통신 작업에서 변경한 것으로 간주하지 않는다.

## 공개방과 작업 동석 구현 후속 검토 (2026-11-04)

사용자가 승인한 계획에 따라 공개방 목록, 링크 참가 화면, 실제 승계에 맞는 퇴장 안내를 구현했다. 기존 방은 목록에 자동 공개하지 않고 새 방은 생성 시 공개 범위를 선택한다. 방 발견은 서버의 로비 정보로 제공하며 게임의 P2P 전송·판정은 유지한다. 누구나 참여하는 공개 목록이며 Discord 커뮤니티 회원 인증은 포함하지 않는다.

작업 메모·수동 상태·AFK 보호/장난 허용·호출 수신 선택과 날짜·시간 기록을 추가했다. 게임 입력이 없는 개발 작업을 자동 자리 비움으로 오해하지 않도록 상태는 수동으로 정한다. AFK 보호는 피격 이동과 들기를 실제 방장 판정에서 차단하고 자기 이동·공격도 막는다. 앉기와 들기를 함께 쓰지 않도록 규칙을 맞추고, 주요 통로의 통나무·텐트를 옮겼으며 앞쪽 장식이 캐릭터를 가릴 때 투명도를 낮춘다.

필드 보기·줌·자기 캐릭터 추적·지원 환경의 Document PIP를 구현했다. 작은 창에는 필드와 참가자 목록을 두고, 상태 편집·채팅은 원래 화면에서 이어간다. 선택한 친구의 상세 정보와 호출은 작은 창에서도 사용한다. PIP를 닫아도 방 연결은 유지한다. 작은 창은 원래 웹 창의 수명에 종속되며 독립 바탕화면 앱은 아니다.

기술 검증 중 방장 승계에서 데이터 채널이 제어 채널보다 먼저 열리면 복구한 참가자를 끊김으로 표시해 들기 연쇄를 해제할 수 있는 경합을 확인했다. 기존 복구 상태를 제어 핸드셰이크 이전에 해제하지 않도록 고치고, 이전 채널의 늦은 콜백도 현재 연결에 적용되지 않게 했다. 해당 순서를 재현하는 회귀 검사를 추가했다.

이번 변경은 ‘개발 중 곁에 머물기’를 직접 돕는다. 휴식/놀이 구역과 경계 규칙은 여전히 미구현이며 개인 AFK 보호로 대체됐다고 보지 않는다. 많은 인원의 긴 메모는 필드에서 줄이거나 겹침을 생략하고 상세 정보에서 읽게 한다. 실제 커뮤니티에서 가독성과 호출 빈도가 편안한지는 후속 사용으로 확인해야 한다. 음성 상태·모바일 통화는 [기술 검토](voice-options.md)에 권한 조건과 미검증 범위를 남겼다. 실행 증거와 공개 배포 여부는 [검증 기록](validation.md)을 따른다.

## 축구공과 작업 동석 보강 (2026-11-04, 규약 v11)

승인된 다섯 항목을 기존 흐름에 연결했다. 축구공은 걸어서 밀고 달려서 더 세게 차며 방장 판정과 복구 묶음을 공유한다. 점수·팀전·다른 플레이어를 공으로 밀어내는 효과는 추가하지 않았다. 모닥불과 통로를 피한 초기 위치를 사용하지만 휴식 구역 보호를 구현한 것은 아니다.

채팅은 오래된 메시지부터 아래로 쌓고 날짜 구분도 같은 방향으로 표시한다. 하단에서는 새 메시지를 따라가고 과거 대화를 읽는 동안에는 최신 이동 버튼을 제공한다. 작업 상태는 기존 수동 계약을 유지하면서 빠른 선택과 참가자 목록 표시를 보강했다. 본인 작업 시간은 이번 입장의 작업 상태 구간만 누적하므로 다른 창에서 개발하는 시간도 포함한다. 재연결·방장 변경은 시간을 초기화하지 않고 페이지 재시작이나 퇴장은 새 세션으로 취급한다.

사용자가 선택한 YouTube 작은 창은 보이는 공식 플레이어를 유지하는 Document PIP다. 기존 필드 PIP와 번갈아 사용하며 작은 창을 닫으면 같은 방의 공유 시각에서 원래 화면에 재생을 복원한다. 전환 중 플레이어를 다시 생성하므로 무중단 음향을 약속하지 않는다. 미지원 브라우저는 보이는 원래 플레이어를 사용한다. 환경음은 오디오 버퍼에서 반복하며, 게임은 Worker 실행 기회·지연 보정·건강 기반 승계를 함께 사용한다. 기기 절전과 모든 참가자의 탭 동결 중 계속 실행되는 서버형 월드로 바뀐 것은 아니다.

123개 회귀 검사, 타입·빌드·Canvas, 16명 루프백 RTC와 격리된 헤드리스 PIP 검사는 기술 근거다. YouTube 재생 API는 브라우저 검사에서 대체했으므로 실제 곡의 광고·자동재생·청취와 실물 모바일 절전은 미검증이다. 공개 배포와 커뮤니티 사용 결과는 이번 로컬 구현 결과와 구분한다.

## 전체 프로젝트 피드백 (2026-11-04)

> 후속 결정: 아래 보호 관련 가치 판단·우선순위는 AI 제안으로, 사용자 답변 후 철회했다. 사용자는 작업 중·자리 비움에도 상호작용하기를 원하며 보호 기능 제거를 승인했다. 화면·상태 표식 개선은 승인, 공개방 관리·게임 소개 확장은 보류했다. 아래 내용은 당시 관찰·제안의 이력으로만 보존한다.

사용자의 전체 피드백 요청으로 현재 작업 폴더의 제품 기준, UI, 물리·상태 계약, 연결·복구, API·DB, 테스트와 기존 화면 산출물을 검토했다. 아래는 검토자의 평가와 후속 제안이며 새 기능의 구현 승인이나 제품 방향 변경이 아니다. 게임 코드는 변경하지 않았다. 이번 실행 근거는 [검증 기록](validation.md#2026-11-04-전체-프로젝트-피드백-검증)에 둔다.

### 종합 평가와 강점

핵심 놀이와 기술 기반을 갖춘 커뮤니티 알파로 평가한다. 다음 우선순위는 휴식과 놀이가 공존하는 규칙, 처음 온 사람의 화면 이해, 서로 다른 환경에서 오래 머무는 경험이다. 실제 이용자의 재방문과 편안함을 확인한 자료는 아직 없다.

- 숲·불빛·색상·캐릭터가 일관되고, 게스트·공개방·초대 링크·혼자 둘러보기로 입장 경로를 제공한다.
- 체력 경쟁 없이 축구공·연쇄 들기·감정표현 등 함께 반응할 소재가 있으며, 작업 상태·메모·개인 작업 시간·PIP는 개발자 동석이라는 목적에 직접 연결된다.
- 개인 듣기와 공유 재생을 분리하고, 들리기 동의·탈출·AFK 보호를 판정에 연결했다. 상태를 자동 AFK로 바꾸지 않는 점도 다른 창에서 개발하는 사용 방식과 맞는다.
- 명령 중복 방지, 입력 잠금, 일관된 체크포인트, 이전 방장 권한 거절, 재접속과 승계의 회귀 검사가 있다. 기존 퇴장 안내 불일치와 작업 동석 기능 부재는 해결된 항목으로 취급한다.

### 기술·운영 피드백

- **실제 장시간 이용 검증:** 기존 16명 루프백과 격리 브라우저 검사는 좋은 기술 근거다. 다음에는 서로 다른 회선, 실제 TURN 경로, 주 창 최소화와 PIP, 방장 이탈, 실제 YouTube 재생을 포함한 모임으로 입장 성공과 복구 시간을 확인해야 한다. 모든 기기가 잠들었을 때 실행을 유지하는 것은 현재 구조의 보장 범위 밖이다. P2P 유지는 확정 방향이다.
- **서버 부하도 별도로 측정:** `CampNetwork.poll`은 안정 상태에서도 응답 후 3초마다 API를 조회한다. 응답 시간을 제외한 계산상 16명은 시간당 약 19,200회이며, 이는 관측된 처리량이나 비용이 아니다. P2P 게임 전송량 감소와 HTTP·D1 부하는 분리해서 평가해야 한다.
- **변경하기 쉬운 구조:** 물리·전송·복구의 모듈 경계와 테스트를 유지한다. `camp.tsx`에는 화면 구성 외에 솔로 명령·입력·프로필 인증·작업 시간의 수명 관리가 함께 있고, 일부 JSX·CSS가 긴 한 줄로 압축돼 있다. 다음 관련 수정에서 읽기 좋게 정리하고 수명 관리를 나누는 편이 좋다. `@ts-check` 적용은 부분적이며 타입 검사 통과가 모든 `.mjs`의 엄격한 검사를 뜻하지 않는다. 전면 재작성은 제안하지 않는다.
- **문서의 현재 상태 정리:** 루트 README는 배포 버전 11과 채팅 최신순을 안내하지만 검증 기록의 마지막 배포는 버전 12이고 현재 채팅은 오래된 것부터 쌓인다. `web/README.md`의 ‘현재 작업 폴더에 이미 적용’이라는 설명과 달리 기본 `.wrangler/state` DB의 `camp_rooms`에는 `title`, `visibility`가 없다. 해당 DB로 실행하면 공개방 조회·생성이 실패할 수 있으므로 현재 스키마를 확인한 뒤 누락 마이그레이션만 적용하도록 안내를 고쳐야 한다. 이번에는 읽기 전용 스키마 확인만 했으며 SQL을 적용하지 않았다.

### 제안하는 다음 순서와 완료 기준

1. 현재 실행 안내·배포 설명을 맞추고, 휴식/놀이 공간 관계와 경계 사례를 정한다. 쉬는 사람 보호와 이미 승인된 놀이가 함께 성립해야 한다.
2. 사람·상태·채팅의 화면 우선순위와 밀집 장면의 라벨을 정리한다. 처음 온 사람이 별도 설명 없이 친구를 찾고, 앉고, 상태를 바꾸고, 채팅한 뒤 필드로 돌아올 수 있는지 본다.
3. 소규모 커뮤니티에서 서로 다른 회선으로 30~60분 함께 사용한다. 참가 성공률, 복구 시간, 원치 않은 방해, 채팅 접근, 다시 방문하려는 이유를 확인한다. 공개 운영의 최소 관리 수단도 이 단계에서 점검한다.
4. 게임 소개는 실제 이용에서 나온 필요에 맞춰 작은 기능부터 확장한다. 상설방·회원 제한·음성 도입은 미정 사항으로 남긴다.

화면 평가는 기존 헤드리스 브라우저 캡처 2개와 Canvas 직접 렌더 1개를 읽은 결과다. 이번에 브라우저·개인 데스크톱을 조작하거나 새 화면 캡처·배포·실인터넷 통신 검사를 수행하지 않았다. 실제 사용성의 확정 결론과 구분한다.

공개방 관리와 게임 소개 확장은 사용자 보류를 유지했다. 기본 로컬 DB의 누락 마이그레이션은 문서에 사실만 바로잡고 실행하지 않았다. 새로운 DB 마이그레이션·공개 배포·전역 설정 변경은 없다. 이번 기술 결과는 [검증 기록](validation.md#2026-11-04-보호-제거화면의도-하네스-검증-규약-v12)에 남겼으며, 실제 커뮤니티 만족도를 입증한 것으로 확대하지 않는다.

후속 사용자 배포 요청에 따라 위 검증 변경을 기존 공개 사이트의 **버전 13·규약 v12**로 배포했다. 공개 HTML·API와 정적 파일 일치 검사를 통과했으며, 기존 공개 접근·D1·런타임 환경을 유지했다. 원래 열어 둔 참가자는 새로고침해야 한다. 이 공개 확인도 실제 커뮤니티 사용성·음원 청취·인터넷 WebRTC 검증을 대신하지 않는다.

## 라디오 자동 재생과 개인 음소거 (2026-11-05)

사용자가 “내 음악듣기를 하지 않아도 모두 재생…본인이 음소거” 계획의 구현·검증을 승인했다. INT-06의 선택형 듣기 참여를 자동 재생과 개인 음소거로 대체했다. 기존 보호 제거와 별개였던 개인 선택을 없앤 것이 아니라, 듣기를 시작해야 했던 흐름을 듣다가 필요하면 음소거하는 흐름으로 변경했다.

- 입장한 사람은 라디오 접근이나 팝업 열기 없이 현재 곡의 공유 시점부터 듣는다. `camp.tsx`와 `music-player.tsx`에서 듣기 설정에 따른 플레이어 생성/파괴 조건을 제거했다.
- `camp-playback.mjs`의 개인 음소거·음량은 공용 음악 명령과 분리했다. 음소거한 방장도 곡 종료를 전달하고, 전체 재생 버튼이 개인 음소거를 강제로 해제하지 않는다.
- 설정·라디오 팝업·플레이어 버튼은 같은 개인 음소거 값을 사용한다. 새 `musicMuted`는 기본 false이며, 예전 `listening: false`를 음소거 의사로 해석하지 않는다. 명시적으로 고른 음소거와 기존 음량은 저장한다.
- 상시 플레이어가 데스크톱 채팅과 모바일 메뉴·이동 조작을 가리지 않도록 배치를 조정했다. 라디오 근처 버튼은 ‘라디오 설정’으로 표시하며 신청곡과 방장 제어에 사용한다.

브라우저 자동 재생 차단, 보이는 공식 플레이어·Document PIP, 기기 절전 제약은 남는다. 실제 YouTube 음원 청취·모바일 기기·커뮤니티 만족도는 기술 검사만으로 확인됐다고 하지 않는다. 별도 제품 결정은 필요하지 않으며 공개 배포는 이번 승인 범위가 아니다. 이번 실행 근거는 [검증 기록](validation.md#2026-11-05-라디오-자동-재생개인-음소거)에 남긴다.

### 후속: 백그라운드에서도 라디오 진행

같은 날 사용자의 “백그라운드에서도 진행되게 해줘” 요청으로 가시성에 따른 앱의 자동 일시정지를 제거했다. 작업 창으로 전환하거나 화면 밖으로 플레이어가 이동해도 재생과 곡 전환을 이어가며, 작은 창은 영상을 보고 싶을 때 선택한다. 개인 음소거는 유지한다. 숨긴 방장 브라우저가 자체 정지해도 모두를 정지시키지 않고, 복귀하면 공유 시점으로 다시 맞춘다. 승계 중 정지는 별개의 공유 시각 계약이므로 유지했다.

코드·회귀 및 모의 가시성의 격리 브라우저 검사로 확인했다. 실제 YouTube 재생, 운영체제 최소화/절전, 모바일의 백그라운드 실행은 미검증이며 플랫폼 자체 제한을 우회하거나 지속 실행을 보장하는 구현은 아니다. 공개 배포는 하지 않았다.

잔불로 줄어도 공동 성장과 해금은 유지하고 방장 승계에서 좌석·개인 대기시간·성장·선택 외형을 함께 복구한다. 방이 끝나면 초기화한다. 개인 소리·라디오·작업 시간·맵 분리와 무관한 보호·관리 기능은 확대하지 않았다. 기술 검사는 [검증 기록](validation.md)에 구분하며 실제 커뮤니티에서의 성장 속도 선호·실물 터치·실인터넷 RTC 검증과 공개 배포는 이번 완료에 포함하지 않는다.

후속 공개 결과: 사용자의 “배포해줘” 요청으로 이 변경을 2026-11-05 기존 공개 사이트 버전 18·규약 v15에 배포했다. 공개 설정·DB·환경 리비전은 유지했다. 공개 HTML·JS/CSS·음원·타이머 Worker를 게시 빌드와 대조하고 입장 API 응답을 확인했다. 앞 문단의 미배포 경계는 이 후속 요청으로 대체하며 실물 기기·커뮤니티 경험의 미확인 범위는 유지한다.

## 신청곡 자동 시작·이름표·휠 조작 검토 (2026-11-05, INT-03·04·06)

사용자가 승인한 신청→바로 함께 듣기, 지형 뒤에서도 친구 이름 알아보기, 필드 위 휠로 배율 조절 흐름을 구현과 대조했다. 현재 곡이 없는 라디오는 일반 참가자가 신청해도 방장 클릭 없이 시작하고, 재생 중인 곡·방장이 멈춘 곡은 새 신청으로 바꾸거나 다시 시작하지 않는다. 개인 음소거와 브라우저 재생 허용 버튼은 공용 자동 시작과 독립이다. 기존 다음 곡 자동 전환·신청 순서·방장 수동 조작·승계를 보존한다.

이름표는 맵과 캐릭터를 모두 그린 뒤 표시해 나무·텐트·통나무에 가려지지 않게 했다. 이름표 클릭도 신체 선택보다 앞세워 보이는 친구를 고를 수 있다. 신체 자체의 깊이·지형 반투명 처리와 개인 숨김·맵 필터는 바꾸지 않는다. 휠은 필드 Canvas에만 연결하고 왼쪽 상단 확대/축소/배율 표시를 제거했다. 채팅·라디오·설정 위 휠과 Ctrl+휠을 가로채지 않으며, 내 캐릭터 따라가기·전체 보기·통나무 집중 보기와 PIP 연결을 유지한다.

163개 회귀, 최종 빌드, 지형 전경 가림 픽셀 검사와 Canvas 이미지, 격리 브라우저의 실제 휠·PIP, 16명 루프백 P2P 자동 시작·승계를 확인했다. 이는 로컬 기술 검증이며 실제 YouTube의 기기별 자동 재생 정책·실물 모바일·커뮤니티 사용 검증과 구분한다. 의도 하네스 사례의 계획/구현/배포 경계를 수동 대조했고, 이번 구현 승인을 공개 배포로 확대하지 않았다. 현재 공개 버전 18에는 이번 후속 변경을 배포하지 않았다.

후속 공개 결과: 사용자 “배포하고 커밋 푸시도 해줘”에 따라 2026-11-05 위 변경과 이어 구현한 모바일 라디오 축소를 기존 공개 사이트 버전 19·규약 v15로 배포했다. 공식 플레이어 영상은 유지하고 모바일 안내·미지원 도구만 줄였다. 공개 HTML·JS/CSS·음원과 타이머 Worker가 최종 검증 빌드와 일치하며 입장 API가 정상임을 확인했다. 앞 문단의 미배포 범위는 이 후속 요청이 대체하고 실물 기기·실제 YouTube 청취·커뮤니티 사용의 미확인 범위는 유지한다.
