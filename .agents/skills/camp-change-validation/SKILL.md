# 불멍 놀이터 변경 검증

## 검사 범위 선택

작업 전 기존 수정과 새 변경을 구분한다. 다른 작업자의 변경을 되돌리거나 배포를 위해 원본 저장소 전체를 임의로 커밋하지 않는다. 프로젝트 규칙은 [AGENTS.md](../../../AGENTS.md), 승인 기준은 [의도 기준](../../../docs/project-intent.md)의 해당 ID와 현재 요청에서 확인한다.

[구조 문서](../../../docs/architecture.md)에서 변경 모듈의 소유권과 계약을 확인하고 실제 명령은 [web/package.json](../../../web/package.json) 및 [실행·배포 안내](../../../web/README.md)에서 확인한다. 아래는 선택 기준이며 모든 변경마다 전체 검사를 요구하지 않는다.

| 변경 | 필요한 검증 |
| --- | --- |
| 규칙·문서·스킬 | 형식과 참조 경로, 확정/미정 구분, 적용·질문·승인 경계. 게임 실행 코드가 안 바뀌면 전체 게임 검사 생략 가능 |
| 물리·들기·무기·상태 계약 | 관련 `web/tests/*.test.mjs` 회귀. 공유 상태 변경이면 스냅샷과 승계도 검사 |
| 입력·UI·캐릭터·음악 | 관련 입력·표시·재생 검사와 typecheck/build. 그림·배치·카메라 변경이면 `test:render`; 결과는 Canvas 직접 렌더임을 표시. 시각 변경은 아래 장면 확인도 적용 |
| 로비·RTC·승계·DB | API·프로토콜·복구 검사, 로컬 Worker를 실행한 뒤 `test:network`. 마이그레이션과 이전 권한 차단 확인 |
| 성능 | 원인에 맞는 측정. `test:metrics`는 동일 조건의 모의 비교이며 실인터넷·호스팅 비용 수치로 해석하지 않음 |

PowerShell에서는 `web/`에서 `npm.cmd`를 사용한다. 표의 명령·검사 범위는 시작점이다. 실패나 새 변경이 없다면 같은 검사를 불필요하게 반복하지 않는다.

## 시각 변경의 장면 확인

신규 자산 작업은 [제작 경로](../../../docs/sprite-authoring.md)의 부분 빌드·Canvas·격리 UI·review 검증을 사용한다. 신규 파이프라인/합성 코드 변경에는 `npm.cmd run test:sprites:pipeline`을 실행한다. 선택 원본 누락·방향/접촉 불일치·기존 자산 비변경·오래된 검토의 거절을 확인한다. 범위가 좁은 데이터/문구 변경에는 이 도구 전체를 강제하지 않는다.

[장면 구성 기준](../../../docs/scene-composition.md)에 따라 영향받는 합성 화면을 실제로 열어 확인한다. UI 배치 변경은 관련 패널·오버레이가 표시된 화면도 대상으로 한다. 기술 검사 통과·화면 검토 결과·미해결/미확인을 구분하고 이미지 경로와 관찰을 기록한다. PASS 로그나 이미지 생성만으로 시각 품질 통과를 선언하지 않는다. 범위 안의 결함은 수정 후 같은 관계를 다시 확인하며, 범위 밖·확인 불가 항목은 완료된 부분과 구분한다. 이 절차는 문서 수정에 게임 검사를 추가하거나 개인 UI 조작·상시 사용자 승인을 요구하지 않는다.

## 이 프로젝트의 변경 경계

- 게임 물리는 방장과 솔로가 같은 시뮬레이션을 사용한다. React 표시 상태나 참가자 메타데이터가 복구 좌표를 덮어쓰지 않도록 한다.
- 필드·명령을 바꾸면 타입, 허용 범위, 전송 필드 목록, 복구 묶음과 통신 버전을 함께 검토한다. 전송 정밀도 조정이 권위 물리를 바꾸면 안 된다.
- 승계에서 캠프 시각·무기·채팅·음악을 일관된 체크포인트로 복구한다. 이전 권한의 메시지는 거절하며, HTTP 생존만으로 게임 건강을 판단하지 않는다.
- 연쇄의 양방향 연결·순환 금지·높이/인원 제한·탈출·동의 해제와 공중 잡기 규칙을 보존한다. 구역 기능을 추가하면 입력에서만 막지 말고 방장 규칙과 복구에서도 일치시킨다.
- 채팅·모달·한글 조합·포커스 이탈 중 게임 입력과 동작이 새지 않는지 확인한다. 개인 듣기·음량이 방 전체 음악 상태를 바꾸지 않는지 구분한다.
- D1은 방과 권한 메타데이터를 보관하며 영구 월드 저장소가 아니다. DB 변경은 새 마이그레이션으로 추가하고 적용 여부를 확인한다. 이미 적용한 SQL을 재실행하지 않는다.

수치와 상세 규칙의 최신 근거는 구조 문서와 코드다. 위 불변 조건을 바꾸는 명시적 요청이 있으면 기존 동작을 무조건 유지하지 말고 필요한 계약과 검사를 함께 갱신한다.
상태 의미를 바꾸면 단순 UI 표시뿐 아니라 이동·피격·들기·공 접촉·전송·승계 중 영향받는 경로를 고른다. 최신 의도에 맞는 동작과 별개로 유지할 개인 선택을 함께 검사한다. 낡은 회귀 검사가 새 승인과 충돌하면 의도 기준의 변경 절차를 적용하고 실패를 숨기지 않는다.

## 배포가 요청된 경우

현재 승인 범위가 배포를 포함하는지 확인하되 이미 받은 승인을 다시 요구하지 않는다. 관련 검사와 산출물을 준비하고 기존 Sites 프로젝트·접근 범위·런타임 바인딩을 유지한다. 배포 준비만 요청받은 작업을 실제 공개로 확대하지 않는다.

DB 변경이 있으면 새 SQL과 적용 대상을 확인한다. 비밀값·로컬 상태는 배포 소스에 포함하지 않는다. 배포 후 상태와 공개 응답이 의도한 산출물인지 확인하고, 필요하면 본인이 만든 검사 방만 정리한다. 문서·하네스 정리만으로 게임을 재배포할 필요는 없다.

## 결과 기록

실행한 명령과 통과/실패, 기존 실패 여부, 산출물·버전과 남은 한계를 구분한다. [검증 기록](../../../docs/validation.md)에 지속적으로 필요한 근거를 남긴다. 실행하지 않은 검사를 통과로 쓰거나 이전 결과를 이번 실행처럼 보고하지 않는다. 사용자 UI 자동화 제한과 실제 브라우저·NAT·터치·커뮤니티 사용의 미검증 범위를 준수한다.
