# 계획 전 의도 인터뷰

사용자의 목적과 원하는 결과를 구체화하고, 그 의도에 맞는 진행 방향과 실행 계획을 정리한다.
요청한 방법을 목적 자체로 단정하거나 AI가 추천한 방향을 사용자가 확정한 의도로 바꾸지 않는다.

## 적용과 호출

- 실제 계획 모드이거나 사용자가 `/plan`, `./plan`, `$plan-interview`, 또는
  “질문으로 의도를 먼저 정리해 줘”처럼 계획 인터뷰를 요청할 때 적용한다.
- 명령 사용법을 묻거나 문자열로 인용한 경우에는 적용하지 않는다.
- 텍스트 명령만으로 실제 모드가 전환되었다고 주장하지 않는다. 인터뷰 절차는 모드와 별도로 적용할 수 있다.
- 명시 호출 예: `$plan-interview 로 새 로비의 목적과 범위를 질문한 뒤 계획해 줘`.

## 맥락 파악과 질문

1. 요청과 기존 답변, 관련 자료를 읽고 확정 사실과 미정 선택을 구분한다.
   저장소에서 직접 확인할 수 있는 파일 위치·현재 동작은 먼저 조사한다.
   관련 업무 스킬은 [프로젝트 스킬 선택 규칙](../../../AGENTS.md#select-skills)에서 필요한 것만 고른다.
2. 이해한 목적·원하는 결과·보존할 조건을 짧게 재서술한다. 요청한 방법과 목적, 설명과 사례,
   제약 사이의 어긋남을 대조하고 불확실하면 구체적인 상황이나 성공·실패 사례로 확인한다.
   이미 분명한 내용까지 매번 동의를 받는 절차로 만들지 않는다.
3. 다음 중 결과를 바꾸는 불명확한 항목을 찾는다.
   - 해결하려는 문제와 지금 바꾸려는 이유, 대상 사용자와 실제 사용 상황
   - 원하는 결과와 구체적인 성공·실패 사례, 참고 사례에서 선호하는 부분
   - 포함·제외 범위, 반드시 보존할 동작과 피하고 싶은 결과
   - 우선순위, 일정·자원 제약, 대안 사이의 선호와 감수할 수 있는 손해
   - 완료 기준과 사용자가 결과를 확인할 방법
4. 질문이 허용된 범위에서 영향이 큰 불확실성부터 필요한 최소 질문을 제시하고 답변을 기다린다.
   사용자에게만 알 수 있는 목적과 선호를 큰 가정으로 메우지 않는다. 선택지에는 실제 결과 차이와
   추천 이유를 설명하되 특정 답으로 유도하지 않는다. 방향을 모르면 구체적인 상황이나 대안을 제시한다.
5. 답변으로 확인된 내용을 반영하고, 해석이 달라졌으면 의도 요약을 갱신한다.
   새로 드러난 모호함·충돌·빠진 사례 중 결과를 바꾸는 것만 후속 질문한다.
   “자연스럽게”, “재미있게”, “간단하게” 같은 말은 이 작업에서 관찰할 수 있는 예로 구체화한다.
   첫 답변만으로 큰 가정을 메우지 않는다. 이미 답한 질문과 사소한 구현 선택은 되묻지 않는다.
6. 목표·주요 범위·우선순위·완료 기준에 결과를 크게 바꿀 미정 사항이 없으면 질문을 마친다.
   질문 수나 회차를 채우기 위해 반복하지 않는다. 단순하고 명확한 요청은 짧게 마칠 수 있다.
   사용자가 “알아서 정해”, “이제 계획해”라고 하면 위임 범위의 합리적 가정을 밝히고 계획한다.
   답하지 않은 필수 선택을 동의로 처리하지 않는다.

## 질문 전달

계획 모드·명시적 인터뷰에서는 목표·선호·우선순위를 알아보는 탐색 질문도 허용하되,
상위 지침과 현재 사용자의 명시적 질문 제한을 우선한다. 일반 작업으로 예외를 확대하지 않는다.
AgentHub에서는 현재 세션의 질문 형식·개수 제한·턴 종료 규칙을 따르고, 밖에서는 제공된 질문 도구나 일반 대화를 쓴다.
질문 이유를 짧게 설명하고 답변을 기다린다. 답변에 의존하는 계획을 확정하거나 작업을 실행하지 않는다.

## 계획과 종료 경계

확정한 목표·포함/제외 범위·핵심 선택과 이유, 남겨둔 가정, 실행 단계와 검증·완료 기준을
작업 크기에 맞게 정리한다. 사용자에게 전달한 계획에는 미정 사항을 확정 사실로 섞지 않는다.
계획 요청 자체는 코드·자산 수정, 커밋, 외부 기록·전송 또는 다른 세션 호출 권한이 아니다.
기존에 승인된 실행 범위와 현재 모드의 실행 제한을 함께 지키며 불필요한 재승인을 요구하지 않는다.
